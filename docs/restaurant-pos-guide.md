# คู่มือใช้งาน POS ร้านอาหาร — BMS

> อ้างอิง: `restaurantPos.ts` · `kitchen.ts` · `storeCapabilities.ts` · `docs/business/pos.md`  
> Archetype: `restaurant` · Capabilities: `RECIPE` · `MODIFIER` · `KITCHEN_WORKFLOW` · `WASTAGE`

---

## ภาพรวม Flow ของร้านอาหาร

```
ตั้งค่าร้าน → เปิดกะ (Shift) → เปิดโต๊ะ (Check) → สั่งอาหาร → ส่งครัว
→ ครัวทำอาหาร (Kitchen Board) → เสิร์ฟ → คิดเงิน → ปิดโต๊ะ → ปิดกะ
```

---

## ส่วนที่ 1 — ตั้งค่าก่อนเปิดใช้งาน

### 1.1 ตั้ง Archetype เป็น Restaurant

ไปที่ **Admin → Settings → ข้อมูลร้าน (Store Profile)**

- ฟิลด์ **ประเภทร้าน** → เลือก `Restaurant`
- บันทึก → ระบบเปิด capabilities: `RECIPE`, `MODIFIER`, `KITCHEN_WORKFLOW`, `WASTAGE` ให้อัตโนมัติ

> ⚠️ ถ้าไม่ตั้ง archetype เป็น `restaurant` ฟีเจอร์จัดโต๊ะทั้งหมดจะใช้ไม่ได้

---

### 1.2 เพิ่มวัตถุดิบและสินค้าในคลัง

ไปที่ **Admin → Products** เพิ่มสินค้า 2 ประเภท:

**วัตถุดิบ (สำหรับตัดสต็อกผ่าน Recipe):**

| สินค้า | หน่วยฐาน | Stock Policy |
|-------|---------|-------------|
| หมูสับ | GRAM | `DIRECT` |

| ข้าวสวย | GRAM | `DIRECT` |
| ใบกะเพรา | GRAM | `DIRECT` |
| น้ำมันพืช | ML | `DIRECT` |
| กุ้งสด | GRAM | `DIRECT` |

### 1.2.1 ตั้งสถานีครัว (Kitchen Station) ก่อน — `9.54`

สถานีครัวเป็น **ทะเบียนจริง** ไม่ใช่ข้อความที่พิมพ์ซ้ำในสินค้าแต่ละตัวอีกต่อไป

ไปที่ **Admin → Stock models → สถานีครัว** แล้วกด "เพิ่มสถานี" (ต้องมีสิทธิ์ `product.edit`)

| ช่อง | ความหมาย |
|-----|---------|
| ชื่อสถานี | ชื่อที่ครัวเห็นบนกระดาน เช่น `ครัวร้อน` |
| รหัสสถานี | เว้นว่างได้ ระบบตั้งให้จากชื่อ |
| ขอบเขต | **ทั้งร้าน** (ค่าแนะนำ) หรือ **เฉพาะสาขา** |
| ลำดับ | เลขน้อยขึ้นก่อนบนกระดานครัวและหน้าสั่งอาหาร |

**ข้อที่ต้องรู้:**

- **สาขาเดียวมีได้หลายสถานี** — ครัวร้อน / ครัวต้ม / ครัวเย็น / บาร์ อยู่ในสาขาเดียวกันได้ทั้งหมด
- **สถานีไม่ใช่สาขา และไม่แยกสต็อก** — สต็อกยังตัดตามสาขาของบิลเหมือนเดิมทุกประการ
- **สถานีเฉพาะสาขาใช้กับบิลของสาขานั้นเท่านั้น** — สาขาอื่นที่ขายเมนูเดียวกันจะเห็นตั๋วในช่อง
  "ไม่ระบุสถานี" (หน้าสินค้าจะเตือน แต่ไม่บล็อกการขาย) จึงแนะนำให้ใช้ **ทั้งร้าน** เป็นค่าตั้งต้น
- **เปลี่ยนชื่อสถานีได้ตลอด** — ตั๋วเก่าเก็บชื่อ ณ เวลาที่ครัวเห็น ประวัติจึงไม่เปลี่ยนตาม
  ส่วนเกณฑ์เวลา (สีบนกระดาน) ย้ายตามชื่อใหม่ให้เอง
- **ปิดสถานีคือปิดใช้งาน ไม่ใช่ลบ** — ตั๋วเก่าและประวัติยังอยู่ครบ · ปิดสถานีที่ยังมีเมนูเปิดขาย
  ผูกอยู่ต้องยืนยันก่อน
- **ยังไม่รองรับการต่อเครื่องพิมพ์แยกตามสถานี**

| ชามะนาวเย็น | CUP | `DIRECT` | บาร์เครื่องดื่ม |

### 1.3 ตั้ง Recipe (สูตรอาหาร)

ไปที่ **Admin → Products → [ชื่อเมนู] → Recipe**

ตัวอย่าง Recipe: **ข้าวกะเพราหมูสับ**

| วัตถุดิบ | ปริมาณ | หน่วย |
|---------|-------|------|
| หมูสับ | 120 | กรัม |
| ใบกะเพรา | 10 | กรัม |
| น้ำมันพืช | 10 | มล. |
| ข้าวสวย | 200 | กรัม |

> ขายหนึ่งจาน = ตัดวัตถุดิบตาม Recipe ทันที  
> แก้ Recipe ทีหลัง **ไม่ย้อนไปเปลี่ยนบิลเดิม** (snapshot)

---

### 1.4 ตั้ง Modifier (ตัวเลือกเมนู)

ไปที่ **Admin → Products → [ชื่อเมนู] → Modifiers**

| Modifier | ตัวเลือก | ราคาเพิ่ม |
|---------|---------|---------|
| ระดับความเผ็ด | เผ็ดน้อย / กลาง / มาก | 0 |
| ไข่ | ไม่ใส่ไข่ / เพิ่มไข่ดาว | +15 |
| ปริมาณข้าว | ข้าวน้อย / ปกติ / เพิ่มข้าว | +10 |
| ระดับความหวาน (เครื่องดื่ม) | หวานน้อย / ปกติ / ไม่หวาน | 0 |

> AI จะเสนอเฉพาะ modifier ที่ตั้งไว้เท่านั้น — ห้ามรับ option ที่ไม่มีใน catalog

---

### 1.5 ตั้งโต๊ะ (Floor Setup)

ไปที่ **Admin → Settings → จัดการโต๊ะ** หรือ **POS → Restaurant → ตั้งค่าโต๊ะ**

**วิธีที่ 1: สร้างอัตโนมัติ**
- กด "สร้างโต๊ะอัตโนมัติ" → ใส่จำนวนโต๊ะ (สูงสุด 50 โต๊ะ)
- ระบบสร้างโซน "โซนหน้าร้าน" และโต๊ะ T01–T(N) ให้อัตโนมัติ

**วิธีที่ 2: สร้างเอง**
- สร้าง **Area (โซน)** ก่อน เช่น: โซนหน้าร้าน, โซนใน, VIP Room, ลานจอดรถ
- เพิ่มโต๊ะในแต่ละโซน กำหนด:
  - **รหัสโต๊ะ** (code): T01, T02, VIP1 ...
  - **ชื่อโต๊ะ**: โต๊ะ 1, โต๊ะ 2, ห้อง VIP ...
  - **จำนวนที่นั่ง** (seats): 2, 4, 6, 8 ...

**สถานะโต๊ะ:**

| สถานะ | ความหมาย | สีที่แสดง |
|------|---------|---------|
| `AVAILABLE` | ว่าง พร้อมรับลูกค้า | เขียว |
| `OCCUPIED` | มีลูกค้านั่งอยู่ มีบิลเปิด | แดง/ส้ม |
| `BLOCKED` | ปิดโต๊ะชั่วคราว (จอง/ทำความสะอาด) | เทา |

---

### 1.6 ลงทะเบียนอุปกรณ์ POS

ไปที่ **Admin → Settings → อุปกรณ์ POS (POS Devices)**

- กด "เพิ่มอุปกรณ์" → ตั้งชื่อ (เช่น "แท็บเล็ตหน้าร้าน", "เคาน์เตอร์แคชเชียร์")
- บันทึก Device Token
- เปิด POS บนอุปกรณ์ → ใส่ Device Token เพื่อเข้าระบบ

---

### 1.7 ตั้งค่าพนักงานและ PIN

ไปที่ **Admin → Settings → พนักงาน**

- เพิ่มพนักงาน กำหนด **Role** และ **PIN** (4–6 หลัก)
- Roles สำหรับร้านอาหาร:

| Role | สิทธิ์หลัก |
|-----|----------|
| Manager | ทุกอย่าง รวมยกเลิกบิล, void, คืนเงิน |
| Cashier | เปิดกะ, รับออร์เดอร์, คิดเงิน |
| Waiter | รับออร์เดอร์ (บางร้านไม่ให้คิดเงิน) |
| Kitchen | ดู Kitchen Board เท่านั้น |

## ส่วนที่ 2 — เปิด-ปิดกะ (Shift)

### 2.1 เปิดกะ (Open Shift)

เมื่อเริ่มกะงาน พนักงานทุกคนที่จะใช้ POS ต้องเปิดกะก่อน

1. เปิดหน้า **POS** → กด **"เปิดกะ"**
2. ใส่ PIN ของพนักงานที่รับเงินสด
3. กรอก **ยอดเงินสดเริ่มกะ (Float)** → เช่น 2,000 บาท
4. กด **ยืนยัน** → กะเปิดแล้ว

> ทุก sale, return, void ในกะนี้จะถูกบันทึกไว้กับกะนี้

---

### 2.2 ปิดกะ (Close Shift)

เมื่อสิ้นสุดกะ:

1. POS → กด **"ปิดกะ"** → ใส่ PIN Manager/Cashier
2. นับเงินสดในลิ้นชัก
3. กรอก **ยอดเงินสดที่นับได้** → ระบบคำนวณ Variance
4. พิมพ์รายงาน Z-Report (รายงานปิดกะ)
5. กด **"ยืนยันปิดกะ"**

**รายงานปิดกะ (Z-Report) แสดง:**
- ยอดขายรวม
- แยกตามช่องทางชำระ (เงินสด / QR / บัตร / โอน)
- จำนวนบิล
- ยอด void / return
- เงินเข้า-ออกลิ้นชักระหว่างกะ
- ยอดเงินที่คาดว่าจะมี vs ที่นับได้ (Variance)

> Manager สามารถดู Shift Report ย้อนหลังได้ที่ **Admin → POS Shifts**

---

## ส่วนที่ 3 — จัดการโต๊ะ (Floor Management)

### 3.1 หน้า Floor View (แผนผังโต๊ะ)

เมื่อเปิด POS ในโหมด Restaurant จะแสดงแผนผังโต๊ะทั้งหมด

- **โต๊ะสีเขียว**: ว่าง — กดเพื่อเปิดบิลใหม่
- **โต๊ะสีแดง/ส้ม**: มีลูกค้า — กดเพื่อดู/แก้ไขบิล
- **โต๊ะสีเทา**: ปิด (Blocked)
- บนโต๊ะที่มีบิล แสดง: จำนวนลูกค้า / ยอดค้างชำระ / จำนวนรายการ / รายการที่ยังไม่ส่งครัว

---

### 3.2 เปิดบิลโต๊ะ (Open Check)

1. กดโต๊ะที่ **AVAILABLE** (สีเขียว)
2. ระบุ **จำนวนลูกค้า** (กี่คน)
3. กด **"เปิดโต๊ะ"**
4. โต๊ะเปลี่ยนเป็น **OCCUPIED**

**ข้อมูลบิลโต๊ะ (Check) ที่บันทึก:**
- รหัสบิล (Check ID)
- โต๊ะที่นั่ง
- จำนวนลูกค้า
- อุปกรณ์ POS และกะที่เปิด
- เวลาเปิดโต๊ะ

---

### 3.3 เพิ่มรายการอาหาร (Add Items)

เมื่อเปิดบิลโต๊ะแล้ว:

1. ค้นหาเมนูจาก catalog (พิมพ์ชื่อ / สแกนบาร์โค้ด)
2. เลือกเมนู → ระบุจำนวน
3. ถ้าเมนูมี **Modifier** → ระบบแสดง popup ให้เลือก (เช่น ระดับเผ็ด, ไข่)
4. ใส่ **Kitchen Note** (ถ้ามี เช่น "ไม่ใส่ผักชี")
5. กด **"เพิ่มรายการ"**

รายการจะอยู่ใน status **NEW** (ยังไม่ส่งครัว) — แสดงจำนวนบนโต๊ะเป็น "unsent"

> สามารถเพิ่มรายการได้หลายรอบ ก่อนกดส่งครัว

---

### 3.4 ส่งครัว (Send to Kitchen)

เมื่อรับออร์เดอร์ครบแล้ว:

1. ตรวจสอบรายการทั้งหมดในบิล
2. กด **"ส่งครัว"**
3. ระบบ:
   - เปลี่ยนสถานะรายการ: `NEW` → `SENT`
   - สร้าง **Kitchen Tickets** ส่งไปยัง Station ที่ตั้งค่าไว้
   - จองสต็อกวัตถุดิบตาม Recipe
   - บันทึก "round" (รอบที่ส่ง)

> ถ้าไม่ส่งครัว จะคิดเงินไม่ได้

**รอบการส่งครัว (Round):**
- ลูกค้าสั่งเพิ่ม → กด "ส่งครัว" อีกครั้ง = Round 2
- ครัวเห็นรายการใหม่แยกต่างหากจาก Round 1

---

### 3.5 ย้ายโต๊ะ (Move Check)

เมื่อลูกค้าต้องการย้ายโต๊ะ:

1. กดโต๊ะที่ต้องการย้าย → กด **"ย้ายโต๊ะ"**
2. เลือกโต๊ะปลายทางที่ **AVAILABLE**
3. ยืนยัน → บิลย้ายไปโต๊ะใหม่ทันที

**เงื่อนไข:**
- โต๊ะปลายทางต้องว่าง (ไม่มีบิลเปิดอยู่)
- ต้องอยู่ในสาขาเดียวกัน

---

### 3.6 คิดเงิน (Settle Check)

เมื่อลูกค้าต้องการชำระ:

1. กดโต๊ะ → กด **"คิดเงิน"**
2. ระบบตรวจสอบ: ต้องไม่มีรายการ **NEW** (ต้องส่งครัวทั้งหมดก่อน)
3. ระบุ **วิธีชำระเงิน**:

| วิธีชำระ | รายละเอียด |
|---------|----------|
| เงินสด | ใส่ยอดที่รับ → ระบบคำนวณทอน |
| QR Code | สแกน QR → รอยืนยัน |
| บัตรเครดิต/เดบิต | รูดบัตร → บันทึกหมายเลขอนุมัติ |
| โอนเงิน | แนบสลิป → รอ admin ยืนยัน |

4. สามารถ **Split Payment** ได้ เช่น ชำระด้วยเงินสดบางส่วน + QR บางส่วน
5. กด **"ยืนยันชำระเงิน"** → บิลเปลี่ยนเป็น **PAID**
6. โต๊ะกลับเป็น **AVAILABLE** พร้อมรับลูกค้าคนต่อไป

---

### 3.7 ยกเลิกบิล (Cancel Check)

กรณีลูกค้ายกเลิก หรือเปิดบิลผิด:

1. กดโต๊ะ → กด **"ยกเลิกบิล"**
2. ต้องใส่ **เหตุผล** (ห้ามว่าง)
3. กด **"ยืนยันยกเลิก"**

**เงื่อนไขยกเลิก:**
- บิลต้องอยู่สถานะ `OPEN` หรือ `CLOSING`
- ต้อง**ยังไม่มี**รายการที่ชำระเงินสำเร็จ
- ระบบยกเลิก kitchen tickets ที่ค้างอยู่อัตโนมัติ

> ถ้าชำระเงินไปแล้ว ต้องทำ **Return** ผ่านหน้า POS Returns แทน

---

## ส่วนที่ 4 — กระดานครัว (Kitchen Board)

### 4.1 เปิดหน้า Kitchen Board

ไปที่ **POS → Kitchen** (หรือเปิดบน tablet ในครัว)

- แสดง Ticket แยกตาม **Station**
- แต่ละ Ticket แสดง: หมายเลขโต๊ะ / เมนู / Modifier / Kitchen Note / เวลาที่ส่ง

---

### 4.2 สถานะ Kitchen Ticket

| สถานะ | ความหมาย | ผู้เปลี่ยน |
|------|---------|---------|
| `NEW` | ออร์เดอร์มาถึงครัวใหม่ | ระบบส่งอัตโนมัติ |
| `PREPARING` | กำลังทำอาหาร | พนักงานครัว |
| `READY` | พร้อมเสิร์ฟแล้ว | พนักงานครัว |
| `SERVED` | เสิร์ฟแล้ว | พนักงานเสิร์ฟ |

> กระดานครัว **เดินสถานะอย่างเดียว** — ไม่ตัดสต็อก ไม่ยกเลิกบิล  
> สต็อกถูกตัดตอนส่งครัว (createOrder) ไม่ใช่ตอนเสิร์ฟ

---

### 4.3 วิธีใช้กระดานครัว

**พนักงานครัวทำตามนี้:**

1. เห็น Ticket ใหม่ → **กด "กำลังทำ"** (NEW → PREPARING)
2. ทำอาหารเสร็จ → **กด "พร้อมเสิร์ฟ"** (PREPARING → READY)
3. พนักงานเสิร์ฟรับของ → **กด "เสิร์ฟแล้ว"** (READY → SERVED)

**Filter ที่ใช้ได้:**
- กรอง Station: ดูเฉพาะงาน "ครัวร้อน" หรือ "บาร์" ฯลฯ
  - ปุ่มกรองมาจาก **ทะเบียนสถานี** (`9.54`) ครัวที่ยังไม่มีงานจึงยังมีปุ่มของตัวเองพร้อมเลข 0
    — "ครัวร้อนว่าง" กับ "ระบบไม่ส่งงานมาให้ครัวร้อน" เป็นคนละเรื่อง
  - เมนูที่ยังไม่ระบุสถานี **ไม่หายจากกระดาน** แต่ไปอยู่ปุ่ม "ไม่ระบุสถานี"
  - สถานีที่เพิ่งถูกปิดใช้งานแต่ยังมีของค้างในครัว ยังมีปุ่มของตัวเองอยู่ท้ายแถบ
- กรองสถานะ: ดูเฉพาะ NEW / PREPARING / READY

---

### 4.4 Station และการตั้งค่า

Station กำหนดที่ **Admin → Products → Stock Policy → Kitchen Station**

| Station | เมนูที่ควรกำหนด |
|--------|--------------|
| ครัวร้อน | ผัด, ทอด, ย่าง |
| ครัวต้ม | แกง, ต้มยำ, ข้าวต้ม |
| ครัวเย็น | ยำ, สลัด, ส้มตำ |
| บาร์เครื่องดื่ม | กาแฟ, ชา, น้ำปั่น, น้ำอัดลม |
| ไม่ระบุ | รายการจะแสดงในช่อง "ไม่ระบุ station" |

## ส่วนที่ 6 — การบันทึกของเสีย (Wastage)

### 6.1 เมื่อใดควรบันทึก

- วัตถุดิบเน่า/หมดอายุ
- อาหารตกหล่น/เสียในกระบวนการทำ
- ของที่ไม่สามารถขายต่อได้

### 6.2 วิธีบันทึก

ไปที่ **Admin → Wastage (ของเสีย)**

1. กด **"บันทึกของเสีย"**
2. เลือกวัตถุดิบ / เมนู
3. ระบุจำนวนและเหตุผล
4. กด **"ยืนยัน"**

> ตัดแล้ว**ย้อนกลับเองไม่ได้** — ต้องปรับสต็อกกลับเป็นอีกรายการ  
> ควรทำทุกวันก่อนปิดร้าน เพื่อให้ตัวเลขสต็อกถูกต้อง

## ส่วนที่ 8 — Checklist รายวัน

### เช้า — ก่อนเปิดร้าน

- [ ] เปิด POS บนทุกอุปกรณ์
- [ ] เปิดกะ — ใส่ยอดเงินสดเริ่มกะ
- [ ] ตรวจสอบสต็อกวัตถุดิบในหน้า Inventory
- [ ] ตรวจสอบโต๊ะว่าสถานะถูกต้อง (ไม่มีบิลค้างจากเมื่อวาน)

- [ ] เปิดบิลโต๊ะทุกครั้งที่ลูกค้านั่ง
- [ ] ส่งครัวทันทีหลังรับออร์เดอร์
- [ ] ดู Kitchen Board ว่า ticket ไม่ค้าง
- [ ] เมื่อลูกค้าขอบิล → คิดเงินทันที

### กลางวัน — เปลี่ยนกะ (ถ้ามี)

- [ ] ส่งต่อโต๊ะที่ยังมีลูกค้าได้ทันที (คนละเครื่อง/กะ คิดเงินได้ปกติ)

### กลางคืน — ปิดร้าน

- [ ] Manager ตรวจสอบ Shift Report ใน Admin → POS Shifts

## ส่วนที่ 9 — การแก้ปัญหาที่พบบ่อย

### ❓ ส่งครัวไม่ได้ — ระบบขึ้น error

**สาเหตุ:** บิลถูกกดส่งครัวพร้อมกันจากหลายอุปกรณ์  
**แก้:** รอสักครู่แล้วลองใหม่ — ระบบใช้ lock ป้องกัน race condition อยู่แล้ว

---

### ❓ คิดเงินไม่ได้ — ขึ้น "มีรายการที่ยังไม่ส่งครัว"

**สาเหตุ:** มีรายการ NEW (สีเหลือง) ค้างอยู่ในบิล  
**แก้:** กด **"ส่งครัว"** ก่อน แล้วค่อยคิดเงิน

---

### ❓ คิดเงินไม่ได้ — ขึ้น "บิลเปลี่ยนระหว่างส่งครัว"

**สาเหตุ:** มีการแก้ไขบิลจากอีกอุปกรณ์พร้อมกัน  
**แก้:** reload หน้า POS → ตรวจสอบรายการ → ส่งครัวใหม่

---

### ❓ ย้ายโต๊ะไม่ได้ — ขึ้น "โต๊ะปลายทางมีบิลเปิดอยู่แล้ว"

**สาเหตุ:** โต๊ะที่เลือกมีลูกค้านั่งอยู่แล้ว  
**แก้:** เลือกโต๊ะอื่นที่ว่าง (สีเขียว)

---

### ❓ ยกเลิกบิลไม่ได้ — ขึ้น "บิลนี้ยกเลิกไม่ได้"

**สาเหตุ:** มีการชำระเงินไปแล้วในบิลนี้  
**แก้:** ต้องทำ **Return** ผ่านหน้า POS → Returns

---

### ❓ Kitchen Board ไม่แสดงออร์เดอร์ใหม่

**สาเหตุ 1:** ยังไม่กด "ส่งครัว" (รายการยัง NEW ใน check)  
**แก้:** กลับไปที่บิลโต๊ะ → กด "ส่งครัว"

**สาเหตุ 2:** Capability `KITCHEN_WORKFLOW` ยังไม่เปิด  
**แก้:** Admin → Settings → Stock Models → เปิด Kitchen Workflow

**สาเหตุ 3:** เมนูไม่มี Kitchen Station กำหนดไว้  
**แก้:** Admin → Products → [เมนู] → Stock Policy → กำหนด Kitchen Station

---

### ❓ สต็อกวัตถุดิบไม่ลด แม้ขายไปแล้ว

**สาเหตุ:** เมนูนั้นยังไม่มี Recipe หรือ Recipe ยังไม่สมบูรณ์  
**แก้:** Admin → Products → [เมนู] → Recipe → เพิ่มส่วนประกอบให้ครบ

---

## ส่วนที่ 10 — สรุปขั้นตอนหน้า POS (Quick Reference)

```
[เริ่มกะ] → เปิดกะ + ใส่ยอดเงินสด

[ลูกค้าเข้าร้าน]
  1. กดโต๊ะสีเขียว → "เปิดโต๊ะ" → ใส่จำนวนลูกค้า
  2. เลือกเมนู → เลือก modifier → กด "เพิ่มรายการ"
  3. (เพิ่มรายการได้หลายรอบ)
  4. กด "ส่งครัว" → ครัวได้รับ ticket
  5. ลูกค้าสั่งเพิ่ม? → เพิ่มรายการ → กด "ส่งครัว" อีกรอบ
  6. ลูกค้าขอบิล → กด "คิดเงิน" → เลือกวิธีชำระ → ยืนยัน
  7. โต๊ะกลับเป็นสีเขียว ✅

[ย้ายโต๊ะ] → กดโต๊ะ → "ย้ายโต๊ะ" → เลือกโต๊ะปลายทาง

[ยกเลิก] → กดโต๊ะ → "ยกเลิกบิล" → ใส่เหตุผล

[ปิดร้าน]
  1. บันทึกของเสีย (Admin → Wastage)
  2. ปิดกะ → นับเงิน → พิมพ์ Z-Report
```
