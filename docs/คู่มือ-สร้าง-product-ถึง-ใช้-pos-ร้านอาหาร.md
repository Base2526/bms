# คู่มือ: สร้าง Product ร้านอาหาร → ใช้ POS

> ฉบับปฏิบัติ — ครอบคลุมตั้งแต่สร้างวัตถุดิบ เมนู Recipe Modifier Kitchen Station จนถึงใช้งาน POS หน้าร้านได้จริง  
> อ้างอิง: `restaurantPos.ts` · `kitchen.ts` · `storeCapabilities.ts` · `shopArchetypes.ts`

---

## ภาพรวม Flow ทั้งหมด

```
ตั้ง Archetype
     ↓
สร้างวัตถุดิบ (DIRECT)
     ↓
สร้างเมนูอาหาร (RECIPE)
     ↓
ตั้ง Recipe (สูตรวัตถุดิบต่อเมนู)
     ↓
ตั้ง Modifier (ตัวเลือกเมนู)
     ↓
กำหนด Kitchen Station ให้แต่ละเมนู
     ↓
ตั้งโต๊ะ (Floor Setup)
     ↓
ลงทะเบียนอุปกรณ์ POS
     ↓
เปิดกะ → เปิดโต๊ะ → สั่งอาหาร → ส่งครัว → คิดเงิน → ปิดกะ
```

---

## ขั้นตอนที่ 1 — ตั้ง Archetype เป็น "Restaurant"

ไปที่ **Admin → Settings → ข้อมูลร้าน (Store Profile)**

1. ฟิลด์ **ประเภทร้าน** → เลือก **`Restaurant`**
2. กด **บันทึก**

ระบบจะเปิด Capabilities ให้อัตโนมัติ:

| Capability | ใช้สำหรับ |
|-----------|---------|
| `RECIPE` | ตัดวัตถุดิบอัตโนมัติเมื่อขายเมนู |
| `MODIFIER` | ตัวเลือกเมนู เช่น เผ็ดน้อย / เพิ่มไข่ |
| `KITCHEN_WORKFLOW` | กระดานครัว (Kitchen Board) |
| `WASTAGE` | บันทึกของเสียประจำวัน |

> ⚠️ **สำคัญ:** ต้องตั้ง Archetype ก่อนสร้าง Product — เพราะ Stock Policy `RECIPE` และฟีเจอร์จัดโต๊ะจะไม่ปรากฏถ้ายังไม่ตั้ง  
> เมื่อร้านมีออร์เดอร์จริงรายการแรกแล้ว **ระบบล็อก Archetype เปลี่ยนไม่ได้อีก**

## ขั้นตอนที่ 2 — สร้างวัตถุดิบ

วัตถุดิบคือสินค้าที่ใช้ใน Recipe เพื่อให้ระบบตัดสต็อกอัตโนมัติเมื่อขายเมนู

ไปที่ **Admin → Products → + เพิ่มสินค้า**

### 2.1 ฟิลด์ที่ต้องกรอก

| ฟิลด์ | ค่าที่ใช้สำหรับวัตถุดิบ |
|------|----------------------|
| ชื่อสินค้า | ชื่อวัตถุดิบ เช่น "หมูสับ", "ใบกะเพรา" |
| หมวดหมู่ | วัตถุดิบ / ของสด / เครื่องปรุง |
| หน่วยฐาน | `GRAM` หรือ `ML` (วัตถุดิบส่วนใหญ่ใช้น้ำหนัก) |
| Stock Policy | **`DIRECT`** |
| ราคา | ไม่ต้องตั้ง (วัตถุดิบไม่ขายตรง) |

### 2.2 ตัวอย่างวัตถุดิบร้านอาหาร

| วัตถุดิบ | หน่วยฐาน | Stock Policy |
|---------|---------|-------------|
| หมูสับ | GRAM | `DIRECT` |
| ไก่สด | GRAM | `DIRECT` |
| กุ้งสด | GRAM | `DIRECT` |
| ใบกะเพรา | GRAM | `DIRECT` |
| น้ำมันพืช | ML | `DIRECT` |
| ข้าวสวย | GRAM | `DIRECT` |
| เส้นผัดไทย | GRAM | `DIRECT` |
| มะนาว | GRAM | `DIRECT` |

> **เคล็ดลับ:** ตั้งสต็อกเริ่มต้น (Opening Stock) ให้ครบทุกรายการหลังสร้าง  
> ไปที่ **Admin → Inventory → Stock Adjustment**

## ขั้นตอนที่ 3 — สร้างเมนูอาหาร

เมนูอาหารคือสินค้าที่ลูกค้าสั่ง ใช้ Stock Policy = `RECIPE` เพื่อเชื่อมกับวัตถุดิบ

ไปที่ **Admin → Products → + เพิ่มสินค้า**

### 3.1 ฟิลด์ที่ต้องกรอก

| ฟิลด์ | ค่าที่ใช้สำหรับเมนูอาหาร |
|------|------------------------|
| ชื่อสินค้า | ชื่อเมนูตามที่ลูกค้าเรียก เช่น "ข้าวกะเพราหมูสับ" |
| หมวดหมู่ | อาหารจานเดียว / เครื่องดื่ม / ของทานเล่น |
| หน่วยฐาน | `PLATE` / `BOWL` / `CUP` / `GLASS` |
| Stock Policy | **`RECIPE`** |
| ราคาขาย | ราคาหน้าร้าน เช่น 79, 89, 149 |
| Kitchen Station | เลือก station ที่ทำเมนูนี้ |

### 3.2 ตัวอย่างเมนูอาหาร

| เมนู | หน่วย | ราคา | Stock Policy | Kitchen Station |
|-----|------|-----:|-------------|----------------|
| ข้าวกะเพราหมูสับ | PLATE | 79 | `RECIPE` | ครัวร้อน |
| ข้าวกะเพราไก่ | PLATE | 75 | `RECIPE` | ครัวร้อน |
| ผัดไทยกุ้งสด | PLATE | 119 | `RECIPE` | ครัวร้อน |
| ต้มยำกุ้ง | BOWL | 149 | `RECIPE` | ครัวต้ม |
| ส้มตำไทย | PLATE | 69 | `RECIPE` | ครัวเย็น |
| ชามะนาวเย็น | CUP | 35 | `DIRECT` | บาร์เครื่องดื่ม |
| กาแฟเย็น | CUP | 45 | `DIRECT` | บาร์เครื่องดื่ม |
| น้ำเปล่า | BOT | 10 | `DIRECT` | — |

> เครื่องดื่มที่ไม่มีส่วนผสมซับซ้อน ตั้งเป็น `DIRECT` ได้
> เมนูที่ยังไม่มี Recipe หรือไม่ต้องการติดตามสต็อก → ใช้ `NON_STOCK` ได้ (ดู §3.3)

---

### 3.3 Stock Policy `NON_STOCK` — ขายได้เลย ไม่ตัดสต็อก

`NON_STOCK` คือ Policy สำหรับเมนูที่ **ไม่ต้องการติดตามสต็อกอะไรเลย** — ระบบบันทึกบรรทัดขายและเก็บรายได้ แต่ไม่ตัดวัตถุดิบและไม่ต้องตั้ง Recipe

#### เมื่อไหร่ควรใช้ `NON_STOCK`

| สถานการณ์ | ตัวอย่าง |
|----------|---------|
| เมนูใหม่ที่ต้องการขายทันที ยังไม่ได้ตั้ง Recipe | เมนูพิเศษวันนี้ เมนูทดลอง |
| รายการที่ไม่มีสต็อกในระบบ จัดการเองนอกระบบ | ขนมจากร้านข้างๆ อาหารเดลิเวอรี่ |
| ค่าบริการ / ค่าธรรมเนียม | ค่าเซอร์วิสชาร์จ ค่าถุงพลาสติก ค่าที่นั่งขั้นต่ำ |
| ของแถม / รายการที่ไม่มีต้นทุนสต็อก | ขนมปังก้อนแจก ซอสพิเศษ |
| ร้านเพิ่งเปิด ยังไม่พร้อมตั้ง Recipe ทุกเมนู | ช่วง soft open |

#### ข้อจำกัดของ `NON_STOCK`

| ข้อ | รายละเอียด |
|----|----------|
| ❌ ไม่รองรับ Modifier | Modifier ต้องคู่กับ `RECIPE` เท่านั้น — ถ้าใส่ Modifier แล้วใช้ NON_STOCK ระบบ error: `MODIFIER_REQUIRES_RECIPE` |
| ❌ ไม่ตัดสต็อกวัตถุดิบ | ต้องนับและจัดการวัตถุดิบเองนอกระบบ |
| ❌ ไม่มีรายงาน Recipe cost | ไม่มีการคำนวณต้นทุนวัตถุดิบต่อจาน |
| ✅ ขายได้ทันที | ไม่ต้องตั้ง Recipe ก่อน |
| ✅ ยังส่ง Kitchen Ticket ได้ | ถ้ากำหนด Kitchen Station ไว้ |
| ✅ บันทึกรายได้และออกใบเสร็จ | บัญชีและรายงานขายทำงานปกติ |

#### วิธีสร้างเมนู NON_STOCK

ไปที่ **Admin → Products → + เพิ่มสินค้า**

1. ตั้งชื่อเมนู เช่น "เมนูพิเศษวันนี้"
2. Stock Policy → เลือก **`NON_STOCK`**
3. หน่วยฐาน → `PLATE` / `PIECE` / `CUP` ตามแต่รายการ
4. ใส่ราคาขาย
5. กำหนด Kitchen Station (ถ้าต้องการให้ Kitchen Board แสดง)
6. กด **"บันทึก"** → ขายได้ทันที ไม่ต้องตั้ง Recipe

#### ตัวอย่างสินค้า NON_STOCK สำหรับร้านอาหาร

| รายการ | หน่วย | ราคา | หมายเหตุ |
|-------|------|-----:|---------|
| เมนูพิเศษวันนี้ | PIECE | 129 | เปลี่ยนทุกวัน ไม่ต้องตั้ง Recipe |
| ขนมปังเนย (แถม) | PIECE | 0 | ของแถมที่ต้องการบันทึกในบิล |
| ค่าเซอร์วิสชาร์จ | PIECE | 50 | เพิ่มลงบิลได้จาก POS |
| ค่าถุงพลาสติก | PIECE | 3 | ตามกฎหมาย บันทึกแยกในบิล |
| ค่าที่นั่งขั้นต่ำ | PIECE | 100 | ห้องส่วนตัว / VIP |
| เมนูทดลอง Chef's Table | PIECE | 299 | ก่อนตั้ง Recipe จริง |
| ขนม/เบเกอรี่จากร้านอื่น | PIECE | 85 | ไม่มีสต็อกใน BMS |

#### เปรียบเทียบ Policy ทั้ง 3 แบบสำหรับร้านอาหาร

| | `DIRECT` | `RECIPE` | `NON_STOCK` |
|--|:--------:|:--------:|:-----------:|
| ตัดสต็อกสินค้า | ✅ ตัดตรง | ❌ | ❌ |
| ตัดวัตถุดิบ | ❌ | ✅ ตามสูตร | ❌ |
| ต้องตั้ง Recipe | ❌ | ✅ | ❌ |
| รองรับ Modifier | ❌ | ✅ | ❌ |
| ส่ง Kitchen Ticket | ✅ | ✅ | ✅ |
| บันทึกรายได้ | ✅ | ✅ | ✅ |
| เหมาะสำหรับ | เครื่องดื่ม / ของขาย | เมนูอาหาร | ค่าบริการ / เมนูไม่ติดตามสต็อก |

> **แนวทางการเลือก:**  
> — เมนูที่มีวัตถุดิบและต้องการตัดสต็อก → **`RECIPE`**  
> — เครื่องดื่มหรือสินค้าที่ติดตามสต็อกเป็นหน่วย → **`DIRECT`**  
> — ค่าบริการ เมนูไม่ตามสต็อก หรือขายด่วนก่อนตั้ง Recipe → **`NON_STOCK`**

## ขั้นตอนที่ 4 — ตั้ง Recipe (สูตรอาหาร)

Recipe คือรายการวัตถุดิบที่ใช้ต่อหนึ่งหน่วยของเมนู — เมื่อขาย ระบบตัดสต็อกตาม Recipe อัตโนมัติ

ไปที่ **Admin → Products → [ชื่อเมนู] → Recipe**

### 4.1 วิธีเพิ่ม Recipe

1. กด **"+ เพิ่มส่วนประกอบ"**
2. เลือกวัตถุดิบจากรายการ
3. ใส่ปริมาณและหน่วย
4. ทำซ้ำจนครบทุกส่วนประกอบ
5. กด **"บันทึก Recipe"**

### 4.2 ตัวอย่าง Recipe: ข้าวกะเพราหมูสับ (1 จาน)

| วัตถุดิบ | ปริมาณ | หน่วย |
|---------|------:|------|
| หมูสับ | 120 | กรัม |
| ใบกะเพรา | 10 | กรัม |
| น้ำมันพืช | 10 | มล. |
| ข้าวสวย | 200 | กรัม |

### 4.3 ตัวอย่าง Recipe: ผัดไทยกุ้งสด (1 จาน)

| วัตถุดิบ | ปริมาณ | หน่วย |
|---------|------:|------|
| กุ้งสด | 80 | กรัม |
| เส้นผัดไทย | 100 | กรัม |
| น้ำมันพืช | 15 | มล. |
| มะนาว | 20 | กรัม |

### 4.4 หลักการสำคัญของ Recipe

- ขาย 1 หน่วย = ตัดวัตถุดิบตาม Recipe ทันที (ตอนส่งครัว)
- **แก้ Recipe ภายหลังไม่ย้อนบิลเดิม** — บิลเก่าใช้ Recipe snapshot ณ เวลาที่สั่ง
- ถ้า Recipe ไม่ครบ สต็อกวัตถุดิบจะไม่ลด → ควรตั้งให้ครบก่อนเปิดขาย

## ขั้นตอนที่ 5 — ตั้ง Modifier (ตัวเลือกเมนู)

Modifier คือตัวเลือกที่ลูกค้าเลือกได้เมื่อสั่งเมนู เช่น ระดับเผ็ด ไข่เพิ่ม ปริมาณข้าว

ไปที่ **Admin → Products → [ชื่อเมนู] → Modifiers**

### 5.1 วิธีเพิ่ม Modifier

1. กด **"+ เพิ่ม Modifier Group"**
2. ตั้งชื่อ Group เช่น "ระดับความเผ็ด"
3. กำหนดว่าเลือกได้กี่ตัวเลือก (min/max)
4. เพิ่มตัวเลือก (Options) พร้อมราคาเพิ่ม (ถ้ามี)
5. กด **"บันทึก"**

### 5.2 ตัวอย่าง Modifier สำหรับเมนูอาหาร

| Modifier Group | ตัวเลือก | ราคาเพิ่ม | Required |
|---------------|---------|:--------:|:-------:|
| ระดับความเผ็ด | เผ็ดน้อย / เผ็ดกลาง / เผ็ดมาก | 0 | ✅ |
| ไข่ | ไม่ใส่ไข่ / เพิ่มไข่ดาว | +15 | ❌ |
| ปริมาณข้าว | ข้าวน้อย / ปกติ / เพิ่มข้าว | +10 | ❌ |
| เนื้อสัตว์ | หมูสับ / ไก่ / กุ้ง / เต้าหู้ | 0 / 0 / +20 / 0 | ✅ |

| Modifier Group | ตัวเลือก | ราคาเพิ่ม | Required |
|---------------|---------|:--------:|:-------:|
| ระดับความหวาน | หวานน้อย / ปกติ / ไม่หวาน | 0 | ✅ |
| น้ำแข็ง | ใส่น้ำแข็ง / ไม่ใส่น้ำแข็ง | 0 | ✅ |
| ขนาด | ปกติ / ใหญ่พิเศษ | +15 | ❌ |

> **กฎของระบบ:** AI และ POS จะเสนอเฉพาะ Modifier ที่ตั้งไว้ — ห้ามรับตัวเลือกที่ไม่มีใน catalog

## ขั้นตอนที่ 6 — กำหนด Kitchen Station

Kitchen Station กำหนดว่าเมนูนี้จะปรากฏที่กระดานครัวสถานีไหน

ตั้งที่ **Admin → Products → [ชื่อเมนู] → Stock Policy → Kitchen Station**

### 6.1 สถานีแนะนำสำหรับร้านอาหารทั่วไป

| Station | เมนูที่ควรกำหนด |
|--------|--------------|
| ครัวร้อน | ผัด, ทอด, ย่าง,炒 |
| ครัวต้ม | แกง, ต้มยำ, ข้าวต้ม, ซุป |
| ครัวเย็น | ยำ, สลัด, ส้มตำ, ลาบ |
| บาร์เครื่องดื่ม | กาแฟ, ชา, น้ำปั่น, น้ำอัดลม |

### 6.2 ผลลัพธ์

- เมื่อ POS ส่งครัว → ระบบสร้าง Kitchen Ticket แยกต่อ Station
- ครัวแต่ละสถานีเห็นเฉพาะงานของตัวเอง ไม่ปะปน

> ถ้าเมนูไม่มี Kitchen Station → จะแสดงในช่อง "ไม่ระบุ Station"  
> ควรกำหนดทุกเมนูเพื่อให้กระดานครัวทำงานได้ถูกต้อง

## Checklist ก่อนเปิดขาย

ตรวจสอบทุกข้อก่อนใช้ POS จริง:

**ด้าน Product:**
- [ ] ตั้ง Archetype = `Restaurant` แล้ว
- [ ] สร้างวัตถุดิบทุกรายการ (Stock Policy = `DIRECT`)
- [ ] ตั้งสต็อกเริ่มต้นวัตถุดิบ (Stock Adjustment)
- [ ] สร้างเมนูอาหารทุกรายการ (Stock Policy = `RECIPE`)
- [ ] ตั้ง Recipe ให้ครบทุกเมนู
- [ ] ตั้ง Modifier ให้เมนูที่มีตัวเลือก
- [ ] กำหนด Kitchen Station ให้ทุกเมนู

**ด้านร้าน:**
- [ ] สร้างโต๊ะในระบบ (Admin → Settings → จัดการโต๊ะ)
- [ ] ลงทะเบียนอุปกรณ์ POS (Admin → Settings → อุปกรณ์ POS)
- [ ] ตั้งพนักงานและ PIN (Admin → Settings → พนักงาน)
- [ ] ทดสอบ Kitchen Board บน tablet ในครัว

## ขั้นตอนที่ 7 — ใช้งาน POS ร้านอาหาร

### 7.1 เปิดกะ (ต้องทำก่อนเริ่มรับออร์เดอร์)

1. เปิด **POS** บนอุปกรณ์ → กด **"เปิดกะ"**
2. ใส่ **PIN** ของพนักงาน
3. กรอก **ยอดเงินสดเริ่มกะ (Float)** เช่น 2,000 บาท
4. กด **"ยืนยัน"**

---

### 7.2 หน้าแผนผังโต๊ะ (Floor View)

| สีโต๊ะ | ความหมาย | สิ่งที่ทำได้ |
|-------|---------|-----------|
| 🟢 เขียว | ว่าง (AVAILABLE) | กดเพื่อเปิดบิลใหม่ |
| 🔴 แดง/ส้ม | มีลูกค้า (OCCUPIED) | กดเพื่อดู/แก้ไขบิล |
| ⬜ เทา | ปิดชั่วคราว (BLOCKED) | ใช้งานไม่ได้ |

บนโต๊ะ OCCUPIED แสดง: จำนวนลูกค้า / ยอดค้างชำระ / รายการที่ยังไม่ส่งครัว

---

### 7.3 เปิดบิลโต๊ะ

1. กดโต๊ะ **สีเขียว**
2. ใส่ **จำนวนลูกค้า** (เช่น 2 คน)
3. กด **"เปิดโต๊ะ"**
4. โต๊ะเปลี่ยนเป็น **สีแดง** (OCCUPIED)

---

### 7.4 สั่งอาหาร

1. ค้นหาเมนูจาก catalog (พิมพ์ชื่อ หรือเลือกจากหมวดหมู่)
2. เลือกเมนู → ระบุจำนวน
3. ถ้ามี Modifier → เลือกตัวเลือก (เผ็ดน้อย, เพิ่มไข่ ฯลฯ)
4. ใส่ **Kitchen Note** ถ้ามี เช่น "ไม่ใส่ผักชี", "แพ้ถั่ว"
5. กด **"เพิ่มรายการ"**

รายการจะอยู่ในสถานะ **NEW** (สีเหลือง) — ยังไม่ถูกส่งครัว  
เพิ่มได้หลายรายการก่อนจะกดส่งครัว

---

### 7.5 ส่งครัว

เมื่อรับออร์เดอร์ครบรอบนี้:

1. ตรวจสอบรายการในบิล
2. กด **"ส่งครัว"**

สิ่งที่เกิดขึ้น:
- สถานะรายการ `NEW` → `SENT`
- ระบบสร้าง Kitchen Ticket ส่งไปกระดานครัวแต่ละ Station
- จองสต็อกวัตถุดิบตาม Recipe
- บันทึก Round (รอบที่ส่ง)

> ⚠️ **ต้องส่งครัวก่อน ถึงจะคิดเงินได้**  
> ลูกค้าสั่งเพิ่ม → เพิ่มรายการ → กดส่งครัวอีกครั้ง = Round 2

---

### 7.6 กระดานครัว (Kitchen Board) — ฝั่งพนักงานครัว

เปิดที่ **POS → Kitchen** บน tablet ในครัว

**วงจรสถานะ Ticket:**
```
NEW → PREPARING → READY → SERVED
```

| ขั้นตอน | ผู้กด | ปุ่ม |
|--------|------|-----|
| ได้รับงานใหม่ | พนักงานครัว | "กำลังทำ" |
| ทำเสร็จ พร้อมเสิร์ฟ | พนักงานครัว | "พร้อมเสิร์ฟ" |
| เสิร์ฟแล้ว | พนักงานเสิร์ฟ | "เสิร์ฟแล้ว" |

แต่ละ Ticket แสดง: หมายเลขโต๊ะ / เมนู / Modifier / Kitchen Note / เวลาที่ส่ง

---

### 7.7 คิดเงิน (Settle Check)

1. กดโต๊ะ → กด **"คิดเงิน"**
2. ระบบตรวจสอบ: ต้องไม่มีรายการ NEW ค้าง (ต้องส่งครัวให้หมดก่อน)
3. เลือกวิธีชำระเงิน:

| วิธีชำระ | รายละเอียด |
|---------|----------|
| เงินสด | ใส่ยอดที่รับ → ระบบคำนวณเงินทอน |
| QR Code | สแกน QR → รอยืนยัน |
| บัตรเครดิต/เดบิต | รูดบัตร → บันทึกหมายเลขอนุมัติ |
| โอนเงิน | แนบสลิป → admin ยืนยัน |

4. Split Payment ได้ เช่น เงินสด 100 + QR ส่วนที่เหลือ
5. กด **"ยืนยันชำระเงิน"**
6. โต๊ะกลับเป็น **สีเขียว** ✅ พร้อมรับลูกค้าถัดไป

---

### 7.8 ย้ายโต๊ะ

กรณีลูกค้าต้องการเปลี่ยนโต๊ะ:

1. กดโต๊ะต้นทาง → กด **"ย้ายโต๊ะ"**
2. เลือกโต๊ะปลายทาง **สีเขียว** (ต้องว่างเท่านั้น)
3. ยืนยัน → บิลย้ายทันที โต๊ะเดิมกลับเป็นสีเขียว

---

### 7.9 ยกเลิกบิล

กรณีเปิดบิลผิด หรือลูกค้าออกไปก่อนสั่ง:

1. กดโต๊ะ → กด **"ยกเลิกบิล"**
2. ใส่ **เหตุผล** (ห้ามว่าง)
3. กด **"ยืนยันยกเลิก"**

> ถ้าชำระเงินไปแล้ว ต้องทำ **Return** แทน (ผ่าน POS → Returns)

---

### 7.10 ปิดกะ

เมื่อสิ้นสุดกะงาน:

1. POS → กด **"ปิดกะ"** → ใส่ PIN Manager
2. นับเงินสดในลิ้นชัก
3. กรอก **ยอดที่นับได้** → ระบบคำนวณ Variance
4. พิมพ์ **Z-Report** (รายงานปิดกะ)
5. กด **"ยืนยันปิดกะ"**

**Z-Report แสดง:**
- ยอดขายรวม แยกตามช่องทางชำระ
- จำนวนบิล / ยอด void / return
- ยอดเงินสดที่คาดว่าจะมี vs ที่นับได้ (Variance)

---

## สรุปคำสั่งเร็ว (Quick Reference)

```
[ตั้งค่าครั้งแรก]
  Admin → ตั้ง Archetype = Restaurant
  → สร้างวัตถุดิบ (DIRECT)
  → สร้างเมนู (RECIPE) + ตั้ง Recipe + Modifier + Kitchen Station
  → ตั้งโต๊ะ + ลงทะเบียน POS + ตั้งพนักงาน

[เริ่มกะ]
  POS → เปิดกะ → ใส่ PIN → ใส่ยอดเงินสด

[รับลูกค้า]
  1. กดโต๊ะเขียว → เปิดโต๊ะ → ใส่จำนวนลูกค้า
  2. เลือกเมนู → Modifier → Kitchen Note → เพิ่มรายการ
  3. กด "ส่งครัว" → ครัวได้รับ ticket
  4. ลูกค้าสั่งเพิ่ม → เพิ่มรายการ → ส่งครัวอีกรอบ
  5. ลูกค้าขอบิล → "คิดเงิน" → เลือกวิธีชำระ → ยืนยัน
  6. โต๊ะกลับเป็นสีเขียว ✅

[ครัว]
  Kitchen Board: NEW → กำลังทำ → พร้อมเสิร์ฟ → เสิร์ฟแล้ว

[ปิดกะ]
  บันทึกของเสีย (Admin → Wastage)
  → ปิดกะ → นับเงิน → พิมพ์ Z-Report
```

## ปัญหาที่พบบ่อย

| ปัญหา | สาเหตุ | วิธีแก้ |
|------|-------|--------|
| คิดเงินไม่ได้ — "มีรายการที่ยังไม่ส่งครัว" | มีรายการ NEW ค้างอยู่ | กด "ส่งครัว" ก่อน |
| Kitchen Board ไม่แสดง ticket | ยังไม่กด "ส่งครัว" | กลับไปบิลโต๊ะ → กดส่งครัว |
| Kitchen Board ไม่แสดง ticket | ไม่ได้เปิด `KITCHEN_WORKFLOW` | Admin → Settings → Stock Models → เปิด |
| Kitchen Board ไม่แสดง ticket | เมนูไม่มี Kitchen Station | Admin → Products → [เมนู] → กำหนด Station |
| สต็อกวัตถุดิบไม่ลดหลังขาย | Recipe ยังไม่ครบ | Admin → Products → [เมนู] → Recipe → เพิ่มส่วนประกอบ |
| ส่งครัวไม่ได้ — error | หลายอุปกรณ์กดพร้อมกัน | รอแล้วลองใหม่ (ระบบมี lock) |
| ย้ายโต๊ะไม่ได้ | โต๊ะปลายทางมีบิลเปิดอยู่ | เลือกโต๊ะอื่นที่ว่าง (สีเขียว) |
| ยกเลิกบิลไม่ได้ | ชำระเงินไปแล้ว | ทำ Return ผ่าน POS → Returns |
