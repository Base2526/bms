# ร่างคู่มือขาย BMS Retail Local รุ่นนำร่องแบบทำมือ

> สถานะ: **ร่างรอเจ้าของอนุมัติ** ห้ามใช้เป็นคำมั่นกับลูกค้าจนกว่าราคา EULA วิธีรับเงิน
> และผู้มีอำนาจอนุมัติจะลงนาม

## หลักปฏิบัติ

- อ้างราคาจาก `apps/web/lib/bms/retailLocalPricing.ts` เท่านั้น ไม่พิมพ์ตัวเลขซ้ำในข้อความสำเร็จรูป
- แจ้งทุกครั้งว่าเป็นรุ่นนำร่อง ไม่ใช่ GA และ license ไม่ใช่ kill switch
- อย่ารับข้อมูลส่วนบุคคลเกินจำเป็น อย่าใส่เบอร์ LINE ID หลักฐานโอน หรือ Activation Code ใน URL/log
- Activation Code ใช้ครั้งเดียว อายุเจ็ดวัน และส่งผ่านช่องทาง onboarding ที่ยืนยันผู้รับแล้ว
- อย่าส่ง ingestion token ให้ลูกค้าและอย่าส่ง Activation Code ในอีเมลทั่วไป

## ขั้นตอนขาย

1. **คุยทาง LINE** — เก็บชื่อร้าน ผู้ติดต่อ ช่องทางติดต่อ ประเภทธุรกิจ OS และความต้องการ หลังได้รับ
   ความยินยอมตามข้อความ PDPA เวอร์ชันที่ใช้อยู่
2. **ส่งใบเสนอราคา** — เลือกรายการจาก config ราคา ระบุ VAT สถานะรุ่นนำร่อง ขอบเขตซัพพอร์ต
   เงื่อนไขไม่คืนเงิน และลิงก์ EULA ที่ฝ่ายกฎหมายอนุมัติ
3. **รับโอน/PromptPay** — ใช้บัญชีที่เจ้าของอนุมัติเท่านั้น ไม่พิมพ์ช่องทางรับเงินที่ยังไม่ตั้งค่า
4. **ตรวจสลิป** — ผู้ตรวจที่ได้รับมอบหมายตรวจยอด ผู้รับ เวลา และรายการกับ statement จริง
   ห้ามให้ AI หรือภาพสลิปอย่างเดียวเป็นผู้ตัดสินสุดท้าย
5. **ออก license/code** — platform admin เปิด `/admin/retail-local-licenses` สร้างรายการด้วย
   `customerReference` ที่ไม่ใช่ PII โดยตรง เลือก Trial หรือ Paid ตามหลักฐาน แล้วเก็บ Activation Code
   ที่แสดงครั้งเดียวไว้ในช่องทางส่งมอบที่ปลอดภัย
6. **เปลี่ยนสถานะเป็น paid** — ถ้าเริ่มจาก Trial ให้ใช้ commercial action `MARK_PAYMENT_REVIEW`
   ระหว่างตรวจ แล้ว `CONVERT_TO_PAID` พร้อม reason, confirmation และ operation id ที่ไม่ซ้ำ
   อย่าสร้าง license ใหม่เพียงเพื่อเปลี่ยนสถานะ
7. **ออกใบกำกับภาษีของ BMS** — ทำในกระบวนการบัญชีนอกระบบตามข้อมูลที่ลูกค้ายืนยัน ขั้นตอนนี้ไม่ได้
   เกิดจาก tax document ของร้านใน BMS
8. **ส่ง code** — ส่ง Activation Code ให้ผู้รับที่ยืนยันแล้วพร้อมคู่มือติดตั้ง ย้ำว่าติดตั้งได้ก่อน activate
   และปัญหา activation ไม่หยุด runtime
9. **ตรวจหลังส่งมอบ** — ใช้ timeline ดู `INSTALLATION_REGISTERED`/`RUNTIME_SEEN` เมื่อร้าน activate แล้ว
   การไม่มี event ไม่ได้แปลว่าร้านไม่ได้ใช้งาน โดยเฉพาะร้านฟรีหรือเครื่องที่ยังไม่ลงทะเบียน

## ข้อความตอบลูกค้าสำเร็จรูป

### รับคำขอ

“ขอบคุณที่สนใจ BMS Retail Local รุ่นนำร่องครับ/ค่ะ ดาวน์โหลดและติดตั้งได้โดยไม่ต้องฝากข้อมูล
หากต้องการให้ช่วยติดตั้ง โปรดยืนยันว่าคุณยินยอมให้เราใช้ข้อมูลติดต่อเพื่อประสานงานเรื่องนี้”

### ส่งใบเสนอราคา

“แนบใบเสนอราคาตามรายการที่เลือก ราคาปัจจุบันอ้างจากหน้าราคา BMS Retail Local และยังไม่รวม VAT
ตามที่ระบุในเอกสาร โปรดตรวจชื่อผู้ซื้อ ขอบเขตซัพพอร์ต และ EULA ก่อนชำระเงิน”

### รอตรวจชำระ

“เราได้รับหลักฐานเพื่อรอตรวจสอบแล้ว สถานะนี้ยังไม่ใช่การยืนยันรับเงิน เมื่อผู้รับผิดชอบตรวจ statement
ตรงกันแล้ว เราจะออกเอกสารและรหัสเปิดใช้งานผ่านช่องทางที่ยืนยันไว้”

### ส่ง Activation Code

“นี่คือ Activation Code แบบใช้ครั้งเดียวและมีอายุเจ็ดวัน กรุณาอย่าส่งต่อ หลังติดตั้งให้เลือก
Activate or Transfer แล้วกรอกรหัส หากเครือข่ายหรือ activation มีปัญหา ระบบร้านยังใช้งานต่อได้”

### Trial หมดอายุ

“ช่วงทดลองตามรายการเชิงพาณิชย์สิ้นสุดแล้ว แต่ระบบและข้อมูลในเครื่องร้านไม่ถูกปิด หากต้องการซื้อ
หรือต่อบริการ โปรดตอบกลับช่องทางนี้เพื่อให้ทีมตรวจรายการ”

## ขั้นตอนย้ายเครื่อง

1. ให้ร้านสร้าง/เลือก backup เข้ารหัสที่เก็บไว้นอกเครื่องเดิม และยืนยันว่ามี recovery identity
2. ติดตั้ง Retail Local รุ่นที่รองรับบนเครื่องใหม่ แล้ว restore ฐานข้อมูล ไฟล์ และ secret bundle พร้อมกัน
3. platform admin ออก Activation Code ใหม่ให้ license เดิม ห้ามสร้างสิทธิซ้ำเพื่อหลบ review
4. ร้านใช้ Windows **Activate or Transfer**, `sudo bms-retail-local-activate --transfer` บน Ubuntu
   หรือ `bms-retail-local activate` บน macOS ตาม target ที่รองรับ
5. ตรวจ event/review ของเครื่องใหม่ แล้ว platform admin เปิด **รายละเอียด → ย้ายมายังเครื่องนี้**
   บนรายการ `REVIEW_REQUIRED` เลือก Installation ID ต้นทางที่เป็น `ACTIVE` ตรวจ ID ปลายทางแล้วกดยืนยัน
   ระบบใช้ `TRANSFER` ใน transaction เดียว: ต้นทางเป็น `TRANSFERRED` ปลายทางเป็น `ACTIVE`
   ประวัติการตรวจสอบเครื่องแสดงผู้ยืนยันและผล `TRANSFER` การ review ต้องไม่หยุดร้าน
6. ตรวจสถานะ Paid ยังอยู่ภายใต้ License เดิม และตรวจยอด/สต็อก/ไฟล์ที่ restore แยกต่างหาก
   ปุ่มนี้ย้ายสถานะการลงทะเบียนเท่านั้น ไม่ได้คัดลอกหรือ restore ข้อมูล

## แบบบันทึกซ้อม staging ก่อนรับเงินจริง

ใช้ร้านทดสอบและยอดสมมติเท่านั้น ไม่ส่งข้อความหรือรับเงินจากลูกค้าจริงในการซ้อม
บันทึกผู้ทำ ผู้ตรวจ release/commit, LIC- อ้างอิง และเวลาเริ่ม/จบในทะเบียนจำกัดสิทธิ์
ห้ามแนบ Activation Code หรือ token ในรายงาน

| ขั้น | ผลที่ต้องเห็น | เวลา/หลักฐาน/ผู้ตรวจ |
| --- | --- | --- |
| ออกใบเสนอราคาและตรวจรายการรับเงินสมมติ | รายการและ VAT ตรง config/มติที่อนุมัติ | ____ |
| ออก code และ activate | Code ใช้ได้ครั้งเดียว; timeline ยืนยันการลงทะเบียน | ____ |
| Trial → payment review → paid | เหตุผล/confirmation/operation id และ audit ครบ; retry ไม่สร้างรายการซ้ำ | ____ |
| ออกใบกำกับภายนอกและส่งมอบจำลอง | ตรวจผู้รับและเลขเอกสาร; ไม่ใช้ tax document ของร้าน | ____ |
| จบเส้นทางขาย | รวมไม่เกิน 30 นาที; ถ้าเกินระบุขั้นที่ติดขัด | ____ |
| ซ้อมย้ายเครื่องแยกต่างหาก | restore → code ใหม่ → transfer; ยอด/สต็อก/ไฟล์ตรงกัน | ____ |

การซ้อม restore ไม่จำกัดให้จบในเวลาเส้นทางขาย ต้องรอ reconciliation ผ่านจริง
เก็บเฉพาะหลักฐานที่ลบข้อมูลส่วนบุคคลและรหัสลับแล้ว และปิดรายการทดสอบตามทะเบียน
