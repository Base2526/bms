# ร่างมติการเปิดขาย BMS Retail Local รุ่นนำร่อง

> สถานะ: **ร่างรอเจ้าของอนุมัติและลงนาม** เอกสารนี้ไม่ใช่ประกาศราคา ข้อผูกพันกับลูกค้า
> หรือนโยบายที่มีผลใช้จริง

วันที่ทบทวนร่าง: 30 ตุลาคม 2026

ราคาที่เสนอทั้งหมดมีแหล่งเดียวใน `apps/web/lib/bms/retailLocalPricing.ts` เอกสารนี้จงใจไม่คัดลอก
ตัวเลข เพื่อไม่ให้ราคาในเอกสารกับระบบต่างกัน

| เรื่องที่ต้องตัดสินใจ | ข้อเสนอ | เหตุผล | มติเจ้าของ/ลายเซ็น/วันที่ |
| --- | --- | --- | --- |
| 1. ราคา | อนุมัติหรือแก้ชุดราคาและ VAT ใน `retailLocalPricing.ts` ก่อนเผยแพร่ โดยทุกช่องทางอ้างจากชุดเดียวกัน | ป้องกันราคาหน้าเว็บ คู่มือ และใบเสนอราคาไม่ตรงกัน | ____________________ |
| 2. ค่า MA ปีที่ 2 ของร้านนำร่อง | เลือกอัตราปกติ `annualSupport` หรืออัตราล็อกนำร่อง `pilotAnnualSupportAlternative` จาก config; ยังไม่เลือกรายการใดแทนเจ้าของ | ต้องวัดต้นทุนก่อนให้สิทธิราคาตลอดไป | ____________________ |
| 3. นิยาม “รุ่นใหญ่” | ข้อเสนอ: v1.x เป็นรุ่นเดียวกัน อัปเดตย่อยฟรี; v2 ขึ้นไปสำหรับ MA ที่ยังมีผล ห้ามบล็อก corrective update ของรุ่นที่ติดตั้ง | นิยามสิทธิรุ่นใหญ่ให้ชัดโดยคง fail-open | ____________________ |
| 4. EULA | ใช้ร่าง `eula-draft-th.md` หลังฝ่ายกฎหมายตรวจเท่านั้น และห้ามมีเงื่อนไขระงับการใช้งานร้าน | สอดคล้องกับหลัก licensing แบบ evidence-only และ fail-open | ____________________ |
| 5. ขอบเขตซัพพอร์ต | ซัพพอร์ตเฉพาะซอฟต์แวร์และ target ที่ประกาศ; ฮาร์ดแวร์/เครือข่าย/อุปกรณ์ต่อพ่วงที่ยังไม่รับรองเป็น best effort | ป้องกันคำรับรองเกินหลักฐานจริง | ____________________ |
| 6. ความช่วยเหลือร้านฟรี | ให้คู่มือติดตั้งและผู้ช่วย AI; ความช่วยเหลือจากคนเป็นแคมเปญรุ่นนำร่องตามข้อเสนอที่ตั้งไว้ ไม่ใช่ SLA ถาวร | รักษาต้นทุนโดยไม่ตัดสิทธิใช้ระบบ | ____________________ |
| 7. ผู้รับผิดชอบเรื่องเงิน | ระบุชื่อผู้รับเงิน ผู้ตรวจสลิป ผู้อนุมัติ Paid และผู้ออกเอกสารภาษีแยกหน้าที่กัน | ลดความผิดพลาดและสร้างหลักฐานตรวจสอบ | ผู้รับเงิน ____ ผู้ตรวจ ____ ผู้อนุมัติ ____ ภาษี ____ |

## สรุปสำหรับเจ้าของหลังซ้อมระบบทดสอบ

งานระบบซ้อมแยกจากการอนุมัติธุรกิจ: Code / Trial → Paid / transfer ทดสอบด้วยรายการสมมติ
แล้วตาม [บันทึกผลซ้อม](rehearsal-2026-10-30.md) ไม่ได้รับเงินจริง ไม่ส่ง Code ให้ลูกค้า
และไม่เปลี่ยนราคาเป็น approved ผลเทสไม่ได้อนุมัติเปิดขายแทนเจ้าของ

ก่อนเริ่มนำร่อง โปรดลงมติ 8 ข้อในตารางข้างบน โดยเตรียมข้อมูลที่ยังขาดดังนี้:

- **ราคาและ MA:** ยืนยันชุดราคา/VAT ใน config และเลือกอัตรา MA ปีถัดไปของร้านนำร่อง
- **สัญญาและสิทธิ:** ให้ผู้ตรวจ EULA ระบุฉบับที่อนุมัติ และยืนยันนิยามรุ่นใหญ่/สิทธิอัปเดต
- **เงินและอำนาจอนุมัติ:** ระบุบัญชีรับเงินที่ใช้จริง พร้อมชื่อผู้ตรวจ ผู้อนุมัติ Paid และผู้ออกภาษี
- **ทีมซัพพอร์ต:** ยืนยันเวลาบริการ ขอบเขตงาน ระยะช่วยติดตั้งฟรี ผู้รับผิดชอบ LINE และทะเบียน MA
- **นำร่องและเครื่องทดสอบ:** ระบุร้าน ผู้รับผิดชอบวันทดสอบ และชุด OS/USB/NAS/อุปกรณ์ต่อพ่วง
  เพื่อซ้อม restore และกระทบยอดจริงก่อนรับรองชุดนั้น

ยังไม่กำหนดวัน deploy; งานหลังนำร่องและการรับรอง GA ต้องอนุมัติ scope/หลักฐานแยกตาม rollout-status

## การนำมติไปใช้

- เจ้าของต้องลงนามครบทุกข้อ หรือระบุข้อความแก้ไขที่ชัดเจน
- EULA ต้องผ่านนักกฎหมายก่อนส่งให้ลูกค้ายอมรับ
- เอกสารขายทุกชิ้นต้องระบุว่าเป็น “รุ่นนำร่อง” จนกว่า GA readiness จะผ่าน
- สถานะเชิงพาณิชย์หมดอายุ ถูกยกเลิก หรืออยู่ระหว่างตรวจสอบ ต้องไม่หยุด POS ข้อมูล backup restore
  update หรือการทำงานของร้าน
