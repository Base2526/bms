# คู่มือการใช้งาน BMS สำหรับร้านอาหาร

> ฉบับปฏิบัติจริง — ครอบคลุมตั้งแต่ตั้งค่าร้าน จนถึงใช้งาน POS จัดโต๊ะประจำวัน  
> อ้างอิง: `restaurantPos.ts` · `kitchen.ts` · `storeCapabilities.ts` · `shopArchetypes.ts`

---

## ภาพรวม Flow ของร้านอาหาร

```
ตั้งค่าร้าน → เปิดกะ (Shift) → เปิดโต๊ะ → สั่งอาหาร → ส่งครัว
→ ครัวทำ (Kitchen Board) → เสิร์ฟ → คิดเงิน → ปิดโต๊ะ → ปิดกะ
```

---

## ขั้นตอนที่ 1 — ตั้งค่าประเภทร้าน (Archetype)

### 1.1 เลือก Archetype เป็น "Restaurant"

ไปที่ **Admin → Settings → ข้อมูลร้าน (Store Profile)**

- ฟิลด์ **ประเภทร้าน** → เลือก **`Restaurant` (ร้านอาหาร)**
- กด **บันทึก**

ระบบเปิด capabilities ให้อัตโนมัติ:

| Capability | ใช้สำหรับ |
|-----------|---------|
| `RECIPE` | ตัดวัตถุดิบอัตโนมัติเมื่อขายเมนู |
| `MODIFIER` | ตัวเลือกเมนู เช่น เผ็ดน้อย, เพิ่มไข่ |
| `KITCHEN_WORKFLOW` | กระดานครัว (Kitchen Board) |
| `WASTAGE` | บันทึกของเสียประจำวัน |

> ⚠️ **สำคัญ:** ถ้าไม่ตั้ง archetype เป็น `restaurant` ฟีเจอร์จัดโต๊ะและกระดานครัวจะใช้ไม่ได้  
> หลังจากร้านมีออร์เดอร์จริงรายการแรก ระบบจะ **ล็อกประเภทร้าน** เปลี่ยนไม่ได้

---

### 1.2 สิ่งที่ Archetype "Restaurant" ทำให้

- AI รับออร์เดอร์หลายเมนูพร้อมกัน ยืนยัน modifier ที่ร้านตั้งไว้เท่านั้น
- ยืนยันรายการ ตัวเลือก และเวลาก่อนส่งเข้าครัวทุกครั้ง
- เสนอ add-on เพียง 1 รายการจากเมนูจริง ไม่แต่งเติมเอง

---

## ขั้นตอนที่ 2 — ตั้งค่าก่อนใช้งาน

### 2.1 เพิ่มสินค้าในระบบ

ไปที่ **Admin → Products** แบ่งสินค้าเป็น 2 กลุ่ม:

**กลุ่ม A — วัตถุดิบ** (Stock Policy = `DIRECT`):

| สินค้า | หน่วยฐาน |
|-------|---------|
| หมูสับ | GRAM |
| ไก่สด | GRAM |
| ข้าวสวย | GRAM |
| ใบกะเพรา | GRAM |
| น้ำมันพืช | ML |
| กุ้งสด | GRAM |

**กลุ่ม B — เมนูอาหาร** (Stock Policy = `RECIPE`):

| เมนู | หน่วย | Kitchen Station |
|-----|------|----------------|
| ข้าวกะเพราหมูสับ | PLATE | ครัวร้อน |
| ผัดไทยกุ้งสด | PLATE | ครัวร้อน |
| ต้มยำกุ้ง | BOWL | ครัวต้ม |
| ส้มตำไทย | PLATE | ครัวเย็น |
| ชามะนาวเย็น | CUP | บาร์เครื่องดื่ม |

---

### 2.2 ตั้ง Recipe (สูตรอาหาร)

ไปที่ **Admin → Products → [ชื่อเมนู] → Recipe**

ตัวอย่าง: **ข้าวกะเพราหมูสับ**

| วัตถุดิบ | ปริมาณ | หน่วย |
|---------|-------|------|
| หมูสับ | 120 | กรัม |
| ใบกะเพรา | 10 | กรัม |
| น้ำมันพืช | 10 | มล. |
| ข้าวสวย | 200 | กรัม |

> ขาย 1 จาน = ตัดวัตถุดิบตาม Recipe ทันที  
> แก้ Recipe ทีหลัง **ไม่ย้อนบิลเดิม** (snapshot)

---

### 2.3 ตั้ง Modifier (ตัวเลือกเมนู)

ไปที่ **Admin → Products → [ชื่อเมนู] → Modifiers**

| Modifier | ตัวเลือก | ราคาเพิ่ม |
|---------|---------|---------|
| ระดับความเผ็ด | เผ็ดน้อย / กลาง / มาก | 0 |
| ไข่ | ไม่ใส่ไข่ / เพิ่มไข่ดาว | +15 |
| ปริมาณข้าว | ข้าวน้อย / ปกติ / เพิ่มข้าว | +10 |
| ระดับหวาน (เครื่องดื่ม) | หวานน้อย / ปกติ / ไม่หวาน | 0 |

---

### 2.4 ตั้งโต๊ะ (Floor Setup)

ไปที่ **Admin → Settings → จัดการโต๊ะ** หรือ **POS → Restaurant → ตั้งค่าโต๊ะ**

**วิธีที่ 1 — สร้างอัตโนมัติ:**
1. กด "สร้างโต๊ะอัตโนมัติ" → ใส่จำนวน (สูงสุด 50 โต๊ะ)
2. ระบบสร้างโซน "โซนหน้าร้าน" และโต๊ะ T01–T(N) ให้อัตโนมัติ

**วิธีที่ 2 — สร้างเอง:**
1. สร้าง **Area (โซน)** เช่น: โซนหน้าร้าน / โซนใน / VIP Room / ลานจอดรถ
2. เพิ่มโต๊ะในแต่ละโซน กำหนด:
   - **รหัสโต๊ะ:** T01, T02, VIP1 ...
   - **จำนวนที่นั่ง:** 2, 4, 6, 8 ...

**สถานะโต๊ะ:**

| สถานะ | ความหมาย | สีที่แสดง |
|------|---------|---------|
| `AVAILABLE` | ว่าง พร้อมรับลูกค้า | 🟢 เขียว |
| `OCCUPIED` | มีลูกค้านั่ง มีบิลเปิด | 🔴 แดง/ส้ม |
| `BLOCKED` | ปิดชั่วคราว | ⬜ เทา |

---

### 2.5 ลงทะเบียนอุปกรณ์ POS

ไปที่ **Admin → Settings → อุปกรณ์ POS**

1. กด "เพิ่มอุปกรณ์" → ตั้งชื่อ เช่น "แท็บเล็ตหน้าร้าน"
2. บันทึก **Device Token**
3. เปิด POS บนอุปกรณ์ → ใส่ Device Token เพื่อเข้าระบบ

---

### 2.6 ตั้งค่าพนักงานและ PIN

ไปที่ **Admin → Settings → พนักงาน**

| Role | สิทธิ์หลัก |
|-----|----------|
| Manager | ทุกอย่าง รวมถึง void / คืนเงิน |
| Cashier | เปิดกะ, รับออร์เดอร์, คิดเงิน |
| Waiter | รับออร์เดอร์ (บางร้านไม่ให้คิดเงิน) |
| Kitchen | ดู Kitchen Board เท่านั้น |

---

## ขั้นตอนที่ 3 — เปิด-ปิดกะ (Shift)

### 3.1 เปิดกะ (Open Shift)

ทำทุกครั้งก่อนเริ่มงาน:

1. เปิดหน้า **POS** → กด **"เปิดกะ"**
2. ใส่ **PIN** ของพนักงาน
3. กรอก **ยอดเงินสดเริ่มกะ (Float)** เช่น 2,000 บาท
4. กด **ยืนยัน** → กะเปิดแล้ว

---

### 3.2 ปิดกะ (Close Shift)

ทำเมื่อสิ้นสุดกะ:

1. POS → กด **"ปิดกะ"** → ใส่ PIN Manager
2. นับเงินสดในลิ้นชัก
3. กรอก **ยอดที่นับได้** → ระบบคำนวณ Variance
4. พิมพ์ **Z-Report** (รายงานปิดกะ)
5. กด **"ยืนยันปิดกะ"**

**Z-Report แสดง:**
- ยอดขายรวม แยกตามช่องทางชำระ (เงินสด / QR / บัตร / โอน)
- จำนวนบิล / ยอด void / return
- เงินเข้า-ออกลิ้นชักระหว่างกะ
- ยอดที่คาดว่าจะมี vs ที่นับได้ (Variance)

> Manager ดู Shift Report ย้อนหลังได้ที่ **Admin → POS Shifts**

---

## ขั้นตอนที่ 4 — จัดการโต๊ะ (Floor Management)

### 4.1 หน้า Floor View

เมื่อเปิด POS ในโหมด Restaurant จะแสดงแผนผังโต๊ะทั้งหมด

- **โต๊ะสีเขียว** = ว่าง → กดเพื่อเปิดบิลใหม่
- **โต๊ะสีแดง/ส้ม** = มีลูกค้า → กดเพื่อดู/แก้ไขบิล
- **โต๊ะสีเทา** = ปิด (Blocked)
- บนโต๊ะที่มีบิล: แสดง จำนวนลูกค้า / ยอดค้าง / รายการที่ยังไม่ส่งครัว

---

### 4.2 เปิดบิลโต๊ะ

1. กดโต๊ะสีเขียว (AVAILABLE)
2. ระบุ **จำนวนลูกค้า** (กี่คน)
3. กด **"เปิดโต๊ะ"**
4. โต๊ะเปลี่ยนเป็น **OCCUPIED** (สีแดง)

---

### 4.3 เพิ่มรายการอาหาร

1. ค้นหาเมนูจาก catalog (พิมพ์ชื่อ หรือสแกนบาร์โค้ด)
2. เลือกเมนู → ระบุจำนวน
3. ถ้ามี **Modifier** → เลือกตัวเลือก (เช่น ระดับเผ็ด, ไข่)
4. ใส่ **Kitchen Note** ถ้ามี เช่น "ไม่ใส่ผักชี"
5. กด **"เพิ่มรายการ"**

รายการอยู่ใน status **NEW** (ยังไม่ส่งครัว) — สามารถเพิ่มได้หลายรอบก่อนกดส่งครัว

---

### 4.4 ส่งครัว (Send to Kitchen)

เมื่อรับออร์เดอร์ครบแล้ว:

1. ตรวจสอบรายการทั้งหมดในบิล
2. กด **"ส่งครัว"**

ระบบจะ:
- เปลี่ยนสถานะรายการ `NEW` → `SENT`
- สร้าง **Kitchen Tickets** ส่งไปยัง Station ที่ตั้งไว้
- จองสต็อกวัตถุดิบตาม Recipe
- บันทึก Round (รอบที่ส่ง)

> ⚠️ **ถ้าไม่ส่งครัว จะคิดเงินไม่ได้**  
> ลูกค้าสั่งเพิ่ม → เพิ่มรายการ → กด "ส่งครัว" อีกครั้ง = Round 2

---

### 4.5 ย้ายโต๊ะ

1. กดโต๊ะที่ต้องการย้าย → กด **"ย้ายโต๊ะ"**
2. เลือกโต๊ะปลายทางที่ **สีเขียว** (AVAILABLE)
3. ยืนยัน → บิลย้ายทันที

> โต๊ะปลายทางต้องว่างเท่านั้น (ไม่มีบิลเปิดอยู่)

---

### 4.6 คิดเงิน (Settle Check)

1. กดโต๊ะ → กด **"คิดเงิน"**
2. ระบบตรวจสอบ: ต้องไม่มีรายการ NEW ค้างอยู่ (ส่งครัวให้หมดก่อน)
3. เลือก **วิธีชำระเงิน**:

| วิธีชำระ | รายละเอียด |
|---------|----------|
| เงินสด | ใส่ยอดที่รับ → ระบบคำนวณทอน |
| QR Code | สแกน QR → รอยืนยัน |
| บัตรเครดิต/เดบิต | รูดบัตร → บันทึกหมายเลขอนุมัติ |
| โอนเงิน | แนบสลิป → admin ยืนยัน |

4. สามารถ **Split Payment** ได้ เช่น เงินสด + QR
5. กด **"ยืนยันชำระเงิน"** → บิลเป็น **PAID** → โต๊ะกลับเป็นสีเขียว ✅

---

### 4.7 ยกเลิกบิล

1. กดโต๊ะ → กด **"ยกเลิกบิล"**
2. ต้องใส่ **เหตุผล** (ห้ามว่าง)
3. กด **"ยืนยันยกเลิก"**

**เงื่อนไข:** บิลต้องยังไม่มีการชำระเงิน — ถ้าชำระแล้วต้องทำ **Return** แทน

---

## ขั้นตอนที่ 5 — กระดานครัว (Kitchen Board)

### 5.1 เปิดหน้า Kitchen Board

ไปที่ **POS → Kitchen** (หรือเปิดบน tablet ในครัว)

- แสดง Ticket แยกตาม **Station**
- แต่ละ Ticket: หมายเลขโต๊ะ / เมนู / Modifier / Kitchen Note / เวลาที่ส่ง

---

### 5.2 สถานะ Kitchen Ticket

| สถานะ | ความหมาย |
|------|---------|
| `NEW` | ออร์เดอร์มาถึงครัวใหม่ |
| `PREPARING` | กำลังทำอาหาร |
| `READY` | พร้อมเสิร์ฟ |
| `SERVED` | เสิร์ฟแล้ว |

---

### 5.3 วิธีใช้กระดานครัว

**พนักงานครัวทำตามนี้:**

1. เห็น Ticket ใหม่ → กด **"กำลังทำ"** (NEW → PREPARING)
2. ทำเสร็จ → กด **"พร้อมเสิร์ฟ"** (PREPARING → READY)
3. พนักงานเสิร์ฟรับของ → กด **"เสิร์ฟแล้ว"** (READY → SERVED)

**Filter ที่ใช้ได้:** กรอง Station / กรองสถานะ

---

### 5.4 ตัวอย่าง Station ที่แนะนำ

| Station | เมนูที่ควรกำหนด |
|--------|--------------|
| ครัวร้อน | ผัด, ทอด, ย่าง |
| ครัวต้ม | แกง, ต้มยำ, ข้าวต้ม |
| ครัวเย็น | ยำ, สลัด, ส้มตำ |
| บาร์เครื่องดื่ม | กาแฟ, ชา, น้ำปั่น |

ตั้งที่ **Admin → Products → [เมนู] → Stock Policy → Kitchen Station**

---

## ขั้นตอนที่ 6 — บันทึกของเสีย (Wastage)

### เมื่อใดควรบันทึก
- วัตถุดิบเน่า / หมดอายุ
- อาหารตกหล่น / เสียในกระบวนการทำ

### วิธีบันทึก
ไปที่ **Admin → Wastage (ของเสีย)**

1. กด **"บันทึกของเสีย"**
2. เลือกวัตถุดิบ / เมนู
3. ระบุจำนวนและเหตุผล
4. กด **"ยืนยัน"**

> ตัดแล้วย้อนกลับเองไม่ได้ — ควรทำทุกวันก่อนปิดร้าน

## Checklist รายวัน

### 🌅 เช้า — ก่อนเปิดร้าน
- [ ] เปิด POS บนทุกอุปกรณ์
- [ ] เปิดกะ — ใส่ยอดเงินสดเริ่มกะ
- [ ] ตรวจสอบสต็อกวัตถุดิบ (Admin → Inventory)
- [ ] ตรวจสอบโต๊ะ — ไม่มีบิลค้างจากเมื่อวาน

### 🍽️ ระหว่างวัน
- [ ] เปิดบิลโต๊ะทุกครั้งที่ลูกค้านั่ง
- [ ] ส่งครัวทันทีหลังรับออร์เดอร์
- [ ] ดู Kitchen Board — ไม่มี ticket ค้าง
- [ ] ลูกค้าขอบิล → คิดเงินทันที

### 🔄 เปลี่ยนกะกลางวัน (ถ้ามี)
- [ ] แคชเชียร์กะเก่าออก X-Report
- [ ] โต๊ะที่มีลูกค้าส่งต่อได้ทันที ไม่ต้องปิด
- [ ] แคชเชียร์กะใหม่เปิดกะ → ใส่ยอดเริ่มกะ

### 🌙 กลางคืน — ปิดร้าน
- [ ] บันทึกของเสียประจำวัน (Admin → Wastage)
- [ ] ตรวจสอบบิลค้าง — แก้ไขหรือยกเลิกให้หมด
- [ ] ปิดกะ — นับเงิน → พิมพ์ Z-Report
- [ ] Manager ตรวจสอบ Shift Report (Admin → POS Shifts)

## Quick Reference — สรุปขั้นตอนหน้า POS

```
[เริ่มกะ]
  → เปิดกะ + ใส่ยอดเงินสด

[ลูกค้าเข้าร้าน]
  1. กดโต๊ะสีเขียว → "เปิดโต๊ะ" → ใส่จำนวนลูกค้า
  2. เลือกเมนู → เลือก modifier → กด "เพิ่มรายการ"
  3. เพิ่มรายการได้หลายรอบก่อนส่งครัว
  4. กด "ส่งครัว" → ครัวได้รับ ticket
  5. ลูกค้าสั่งเพิ่ม? → เพิ่มรายการ → กด "ส่งครัว" อีกรอบ
  6. ลูกค้าขอบิล → "คิดเงิน" → เลือกวิธีชำระ → ยืนยัน
  7. โต๊ะกลับเป็นสีเขียว ✅

[ย้ายโต๊ะ]
  → กดโต๊ะ → "ย้ายโต๊ะ" → เลือกโต๊ะปลายทาง

[ยกเลิกบิล]
  → กดโต๊ะ → "ยกเลิกบิล" → ใส่เหตุผล

[ปิดร้าน]
  1. บันทึกของเสีย (Admin → Wastage)
  2. ปิดกะ → นับเงิน → พิมพ์ Z-Report
```

## การแก้ปัญหาที่พบบ่อย

### ❓ ส่งครัวไม่ได้ — error
สาเหตุ: บิลถูกกดส่งครัวพร้อมกันจากหลายอุปกรณ์  
แก้: รอสักครู่แล้วลองใหม่ — ระบบใช้ lock ป้องกัน race condition

### ❓ คิดเงินไม่ได้ — "มีรายการที่ยังไม่ส่งครัว"
สาเหตุ: มีรายการ NEW (สีเหลือง) ค้างอยู่  
แก้: กด **"ส่งครัว"** ก่อน แล้วค่อยคิดเงิน

### ❓ คิดเงินไม่ได้ — "บิลเปลี่ยนระหว่างส่งครัว"
สาเหตุ: มีการแก้ไขบิลจากอีกอุปกรณ์พร้อมกัน  
แก้: reload POS → ตรวจสอบรายการ → ส่งครัวใหม่

### ❓ ย้ายโต๊ะไม่ได้ — "โต๊ะปลายทางมีบิลเปิดอยู่"
สาเหตุ: โต๊ะที่เลือกมีลูกค้าอยู่แล้ว  
แก้: เลือกโต๊ะอื่นที่ว่าง (สีเขียว)

### ❓ ยกเลิกบิลไม่ได้ — "บิลนี้ยกเลิกไม่ได้"
สาเหตุ: มีการชำระเงินในบิลนี้แล้ว  
แก้: ทำ **Return** ผ่าน POS → Returns

### ❓ Kitchen Board ไม่แสดงออร์เดอร์ใหม่
สาเหตุที่ 1: ยังไม่กด "ส่งครัว"  
แก้: กลับไปที่บิลโต๊ะ → กด "ส่งครัว"

สาเหตุที่ 2: `KITCHEN_WORKFLOW` ยังไม่เปิด  
แก้: Admin → Settings → Stock Models → เปิด Kitchen Workflow

สาเหตุที่ 3: เมนูไม่มี Kitchen Station กำหนด  
แก้: Admin → Products → [เมนู] → Stock Policy → กำหนด Kitchen Station

### ❓ สต็อกวัตถุดิบไม่ลดหลังขาย
สาเหตุ: เมนูนั้นไม่มี Recipe หรือ Recipe ยังไม่ครบ  
แก้: Admin → Products → [เมนู] → Recipe → เพิ่มส่วนประกอบให้ครบ
