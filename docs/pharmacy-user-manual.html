คู่มือนี้อธิบายการใช้งานระบบ Pharmacy Intake ใน BMS ตั้งแต่การรับเคสจากลูกค้า ผ่าน LINE OA หรือ Pharmacy Intake Lab ไปจนถึงการตรวจสอบและส่งคำแนะนำโดยเภสัชกรที่มีใบอนุญาต

⚠️ ข้อกำหนดสำคัญ

ระบบนี้เป็น AI ที่ช่วยเก็บข้อมูลอาการเบื้องต้นเท่านั้น ไม่วินิจฉัยโรคหรือแนะนำยา การอนุมัติ ปฏิเสธ หรือส่งต่อเคสต้องกระทำโดยเภสัชกรที่มีใบอนุญาต (is_licensed_pharmacist=true) เท่านั้น ห้ามใช้ข้อมูลผู้ป่วยจริงในการทดสอบ

สถานะเคส

สถานะความหมายขั้นตอนถัดไป
COLLECTING_INFORMATION AI กำลังซักถามข้อมูลจากลูกค้า รอลูกค้าตอบครบ
PENDING_CONFIRMATION ข้อมูลครบแล้ว รอลูกค้ายืนยันความถูกต้อง รอลูกค้ากด "ยืนยัน"
WAITING_FOR_PHARMACIST รอเภสัชกรตรวจสอบ — เคสเข้า Queue แล้ว เภสัชกรตรวจและตอบกลับ
REFER_TO_DOCTOR ระบบประเมินว่าควรพบแพทย์เร่งด่วน เคสปิดอัตโนมัติ ลูกค้าได้รับข้อความแล้ว
EMERGENCY_REFERRAL ฉุกเฉิน — ส่งข้อความฉุกเฉินถึงลูกค้าทันที เคสปิดอัตโนมัติ
COMPLETED เภสัชกรอนุมัติและส่งคำแนะนำแล้ว —

การบริหาร Protocol

วงจรชีวิต Protocol

Protocol คือชุดคำถามและกฎประเมินสำหรับอาการหนึ่งๆ (เช่น ไข้ ปวดหัว ไอ) ต้องผ่านกระบวนการอนุมัติก่อนใช้งานจริง

ขั้นตอน

DRAFT บันทึกร่าง
สร้างหรือแก้ไข Protocol ผ่าน /admin/pharmacy-protocols ระบบ validate JSON Schema, field references และ condition depth (<5 ชั้น, <100 clauses) ก่อนบันทึก
สามารถแก้ไขได้เสรี — ยังไม่มีผลต่อระบบ Production
PENDING_REVIEW ส่ง Review
กด "Submit for Review" เมื่อ Protocol สมบูรณ์ ขณะ PENDING_REVIEW จะแก้ไขไม่ได้ ต้อง Reject กลับมา DRAFT ก่อน
รอเภสัชกรที่มีใบอนุญาตตรวจสอบเนื้อหาทางคลินิก
APPROVED อนุมัติ (ยังปิดอยู่)
เภสัชกรที่มีใบอนุญาตกด Approve — ตั้ง clinicallyApproved=true และบันทึก reviewedBy/At แต่ enabled ยังเป็น false
ยังไม่ Active ใน LINE OA หรือ Lab จนกว่า Administrator จะ Enable
APPROVED + enabled เปิดใช้งาน
Administrator กด Enable — Protocol พร้อมรับ Trigger จาก LINE OA และปรากฏใน Lab โดย protocol_key ต้องอยู่ใน PHARMACY_PROTOCOLS_ENABLED ด้วย
Trigger Terms ห้ามชนกับ Protocol อื่นที่ Active อยู่
Disabled ปิดใช้งาน
Disable Protocol — หยุด Trigger และ Starter ทันที เคสที่กำลังดำเนินอยู่ไม่ได้รับผลกระทบ สามารถ Enable กลับมาได้
⚠️ เงื่อนไขที่ Runtime ต้องครบ 4 ข้อ

Protocol จะ Active ใน LINE OA และ Lab ก็ต่อเมื่อ: status=APPROVED และ clinically_approved=true และ enabled=true และ protocol_key อยู่ใน PHARMACY_PROTOCOLS_ENABLED ขาดข้อใดข้อหนึ่ง — ไม่ Active

Pharmacy Intake Lab

Lab คือสภาพแวดล้อมจำลองที่ /admin/pharmacy-intake-lab ใช้ทดสอบ Protocol โดยไม่ต้องส่งข้อความจริงผ่าน LINE OA

วิธีใช้งาน Lab

กด "รีเซ็ต session" ก่อนทุก Test Case
ป้องกัน State จาก Test Case ก่อนหน้าปะปนกัน
พิมพ์หรือคัดลอกข้อความทดสอบทีละบรรทัด
กด Starter "ไข้" หรือพิมพ์ "ปวดหัว" เพื่อเริ่ม Protocol ที่ต้องการ
ตรวจสอบ Phase และผลลัพธ์
Lab แสดง phase/state ปัจจุบัน — ตรวจว่าตรงกับ Expected ในคู่มือ QA

Test Cases หลักที่ควรทดสอบ

Test Caseสิ่งที่ทดสอบผลที่คาดหวัง
TC-01 พิมพ์ "มีปวดหัวไหม" ขณะอยู่ใน mode ซื้อสินค้า ถามยืนยัน intent ใหม่ ไม่ตอบ "ไม่พบสินค้าปวดหัว"
TC-02 Full clinical flow ปวดหัวปกติ (13 ขั้นตอน) ได้รับหมายเลขเคส เคสปรากฏใน Queue
TC-03 ส่งข้อความทั่วไปแทรกระหว่าง Intake ข้อความไม่ถูกบันทึกเป็นคำตอบ Clinical
TC-06 พิมพ์อาการฉุกเฉิน "หายใจไม่ออก" ระหว่าง Intake ข้อความฉุกเฉินทันที หยุดถาม Session เป็น WAITING
TC-07 ตอบ "ไม่ยินยอม" Session รีเซ็ต ไม่มีเคสใน Queue

Tenancy Isolation

ทุก Query, Mutation และ Assessment ผูกกับ tenant_id — Tenant A ไม่สามารถเข้าถึงข้อมูลของ Tenant B ได้ไม่ว่าจะผ่าน GraphQL ใดก็ตาม

Audit Queries (Read-Only)

ตรวจสอบสถานะ Protocol และ Assessment ด้วย Query ต่อไปนี้ (ใช้ Role ของ Tenant ทดสอบเท่านั้น)

-- Protocol lifecycle และ activation state
SELECT id, protocol_key, version, status,
       clinically_approved, enabled, display_label,
       trigger_terms, reviewed_by, reviewed_at
FROM bms_pharmacy_protocols
WHERE tenant_id = '<tenant-id>'::uuid
ORDER BY protocol_key, version DESC;

-- Assessment outcome (ไม่ดึง raw health payload)
SELECT id, protocol_id, status, risk_level,
       completeness_status, patient_relationship,
       consent_status, missing_fields, created_at, closed_at
FROM bms_pharmacy_assessments
WHERE tenant_id = '<tenant-id>'::uuid
  AND id = '<assessment-id>'::uuid;

-- Event trail
SELECT action, previous_state, next_state, meta, created_at
FROM bms_pharmacy_assessment_events
WHERE tenant_id = '<tenant-id>'::uuid
  AND assessment_id = '<assessment-id>'::uuid
ORDER BY created_at;
ℹ️ สิ่งที่ไม่ควรอยู่ใน Audit Meta

ตรวจสอบว่า Event Meta ไม่มี: raw conversation, medical_info, complaint, summary หรือ PII ใดๆ — เนื้อหาเหล่านี้ถือเป็น Bug ด้านความปลอดภัย
