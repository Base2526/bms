# คู่มือเริ่มใช้ BMS POS+ ร้านค้าปลีกและค้าส่ง

## คู่มือนี้เหมาะกับใคร

ใช้กับร้านขายสินค้าหน้าเคาน์เตอร์ ร้านค้าส่งที่ขายสินค้าจากคลัง และคาเฟ่ที่ขายหน้าเคาน์เตอร์แบบทั่วไปโดยไม่เปิดบิลโต๊ะหรือส่งครัว ผู้เริ่มต้นจะสร้างสินค้า รับของเข้าหนึ่งรายการ เปิดกะ ขายเงินสด ตรวจใบเสร็จและยอดคงเหลือ แล้วปิดกะได้ ตัวอย่างใช้ร้านและสินค้าสมมติทั้งหมด

**เตรียมก่อนเริ่ม:** บัญชีเจ้าของร้าน สาขาที่จะฝึก ผู้ขายหนึ่งคน ผู้ตรวจสิทธิ์อีกคนเมื่อจะทดลอง Void/คืนเงิน เครื่อง POS ที่จับคู่ เงินทอนจริง และสินค้าฝึกหนึ่งชิ้นที่ไม่ใช่สินค้า lot/serial/ของชั่ง หากร้านจด VAT ให้ผู้รับผิดชอบบัญชีตรวจการตั้งค่าภาษีก่อนขายจริง

## ใช้งาน BMS POS+ Desktop สำหรับร้านค้าปลีกและค้าส่ง

**ผู้ทำ:** แคชเชียร์ `pos.sell` บนเครื่องที่จับคู่และเปิดกะ; ผู้จัดการที่มีสิทธิ์คืน/ยกเลิกตรวจบิลและอนุมัติตามงาน ตัวอย่างนี้ใช้สินค้าฝึก `TRAIN-WATER-001` หนึ่งชิ้นและไม่รับเงินจริง

1. หลังเปิดกะ แอปเข้า **ขาย** ที่ `/pos/app` ตรวจชื่อร้าน สาขา และสถานะออนไลน์ ค้น SKU/ชื่อ หรือสแกนบาร์โค้ด เลือก variant `STD` หรือ Pack ที่ผู้ดูแลสร้างไว้จริง ตรวจชื่อ จำนวน หน่วย ราคา และสต็อกพร้อมขายก่อนเพิ่มตะกร้า ราคาของ Pack ต้องมาจาก Product packs; ถ้าค้นไม่พบให้ตรวจ `RETAIL_POS`, variant, บาร์โค้ด และสต็อกสาขาใน Admin
2. ในตะกร้าตรวจยอดจากหน้าจอ แล้วไป **ชำระเงิน** เลือกวิธีที่ร้านตั้งค่าไว้ ถ้าฝึกเงินสดด้วยบิล 20 บาท กรอกเงินรับ `100.00` และตรวจเงินทอน `80.00` เมื่อไม่มีส่วนลดหรือภาษีเพิ่ม กดยืนยันครั้งเดียว รอ **ชำระเงินสำเร็จ**, **เลขที่ใบเสร็จ** และตัวอย่างใบเสร็จ; **พิมพ์ใบเสร็จ** ใช้เมื่อเครื่องพิมพ์ผ่านการทดสอบแล้ว
3. กด **ขายรายการใหม่** หลังตรวจผล หากผลชำระค้างหรือเน็ตหลุด ให้เปิดบิลเดิม/ประวัติและตรวจยอดก่อนกดใหม่ ตัวเลขเงินที่ลูกค้ายื่นไม่ใช่ยอดขาย บิล 20 บาทเพิ่มเงินสดสุทธิ 20 บาทหลังทอน
4. เลือก **คืน** ที่แถบข้างเพื่อเปิดหน้าขายเต็มภายในแอป ค้นบิลเดิม เลือกบรรทัดและจำนวนที่คืน ระบุเหตุผลและให้ผู้มีสิทธิ์ `order.return`/`payment.refund` ดำเนินการ ตรวจยอดเงินคืนและการคืนสต็อกของ lot/variant จากผลเซิร์ฟเวอร์ การ Void ต้องใช้ PIN ผู้อนุมัติอีกคนและอยู่ในกะที่ยังเปิด; อย่าลบตะกร้าหรือแก้สต็อกแทนการคืน
5. ไป **กะ** เพื่อตรวจยอดและบิลค้าง นับเงินสดทั้งหมด กรอกยอดนับจริง แล้วปิดกะด้วยผู้มี `pos.shift.close` ตรวจรายงานกะและส่วนต่าง หากปิดไม่ได้ให้ตรวจบิลค้าง สิทธิ์ PIN และการเชื่อมต่อก่อน

**ค้าส่ง:** ขั้นราคา Wholesale steps และ Pack ตั้งใน Admin ก่อนขาย ตรวจราคาในตะกร้าตามจำนวนจริง หากเลือกขายเชื่อ ต้องมีข้อมูลลูกค้า สิทธิ์และวงเงินตามกฎเซิร์ฟเวอร์; การขายเชื่อไม่เพิ่มเงินสดในลิ้นชัก ภาพที่ 1–2 ใช้ร่วมกันเฉพาะขั้นสร้างเครื่องและจับคู่ ไม่ได้แสดงหน้าขายปลีกหรือยืนยันธุรกรรม

## สร้างสินค้าและรับของเข้าที่สาขา

**ผู้ทำ:** ผู้ดูแลสินค้าที่มี `product.edit`; ผู้สร้างและผู้รับใบสั่งซื้อมีสิทธิ์ซื้อและรับสินค้าตามบทบาท; ผู้ตรวจยอดสต็อกมีสิทธิ์ดูคลัง

1. เข้า **Products** ที่ `/admin/products` กด **เพิ่มสินค้า** เลือก template **สินค้าทั่วไป** แล้วกรอกช่อง **SKU**, **ชื่อสินค้า**, **รูปแบบสต็อก**, **หน่วยฐาน**, **ราคาขาย**, และ **ช่องทางขาย** ตามตาราง ตัวอย่างนี้ขายเป็นชิ้นเดียว จึงใช้ variant `STD` และไม่ต้องสร้าง Pack; Pack ใช้เมื่อหนึ่งหน่วยขายมีหลายหน่วยฐานจริง
2. ถ้าหน้าแสดง **ประเภท VAT** ให้เลือกตามการจัดประเภทที่ผู้รับผิดชอบบัญชียืนยัน อย่ากรอก VAT เป็นค่าที่เดาเอง ช่องต้นทุนให้กรอกต้นทุนจริงเมื่อทราบ; ถ้ายังไม่ทราบอย่าใช้ศูนย์แทน แล้วบันทึก ตรวจว่าสินค้าแสดงในรายการและค้นด้วย SKU ได้
3. ไปที่ **Purchase** ที่ `/admin/purchase` สร้างใบสั่งซื้อกับผู้จำหน่ายสมมติ ใส่ SKU `TRAIN-WATER-001`, variant `STD`, จำนวน 10 และต้นทุนต่อหน่วยที่ตรวจแล้ว จากนั้นเปิดใบเดิม กดรับสินค้า เลือก **สาขาทดสอบ** และกรอกจำนวนที่รับจริง 10 ตรวจผลว่ารับเข้าที่สาขานี้ ไม่ใช่สาขาอื่น หากไม่มีสิทธิ์รับ ให้ผู้จัดการมอบสิทธิ์ที่ตรงงาน
4. เปิดหน้าสต็อกหรือรายการสินค้า ตรวจจำนวนพร้อมขายก่อนเริ่มขาย ตัวเลขตั้งต้น 10 นี้มาจากการรับของ ไม่ใช่การพิมพ์จำนวนลงในช่องราคาสินค้า

| ช่องในหน้าสินค้า | ตัวอย่างสำหรับฝึก | ความหมาย |
| --- | --- | --- |
| SKU | TRAIN-WATER-001 | รหัสไม่ซ้ำของสินค้านี้ |
| ชื่อสินค้า | น้ำดื่มขวดฝึก 600 มล. | ชื่อที่ผู้ขายค้นและลูกค้าเห็นในบิล |
| รูปแบบสต็อก | DIRECT | ขายหนึ่งชิ้นแล้วตัดหนึ่งหน่วยจากคลังสาขา |
| หน่วยฐาน / variant | ชิ้น / STD | หน่วยที่นับในคลังและตัวเลือกขายพื้นฐาน |
| ช่องทางขาย | RETAIL_POS | ทำให้เครื่องขายปลีกค้นและขายสินค้านี้ได้ |
| ราคาขาย | 20.00 บาท | ราคาต่อชิ้นก่อนกฎส่วนลดหรือภาษีของร้าน |
| ประเภท VAT | ตามที่บัญชีร้านยืนยัน | แสดงเมื่อร้านตั้งค่า VAT; อย่าเดาค่าเพื่อผ่านฟอร์ม |
| จำนวนรับเข้า | 10 ชิ้น ที่สาขาทดสอบ | ต้องมาจากใบรับของที่ยืนยันแล้ว |

**ถ้าค้นไม่เจอ:** ตรวจว่าสินค้า Active, SKU ถูก, มี variant, เปิด `RETAIL_POS`, เครื่องอยู่สาขาถูก และสาขานั้นมีสต็อกพอ สินค้า PACK ต้องตั้งจำนวนต่อแพ็กและราคาแพ็กใน Product packs แยกจากราคาหน่วยฐาน

## ลองขายเงินสดหนึ่งรายการ

**ผู้ทำ:** แคชเชียร์ที่มี `pos.sell` บนเครื่องและกะที่เปิดแล้ว ตัวอย่างใช้สินค้าฝึกหนึ่งชิ้น ราคา 20 บาท รับธนบัตร 100 บาท

1. ที่ `/pos` เลือกแท็บ **ขาย** ตรวจสาขาที่หัวจอ เลือกผู้ขาย ใส่ PIN แล้วค้น `TRAIN-WATER-001` หรือสแกนบาร์โค้ดที่ผูกกับสินค้าจริง กดเลือก variant `STD` และจำนวน 1 ตรวจตะกร้าว่าชื่อสินค้า ราคา และจำนวนถูกต้อง
2. เลือก **เงินสด** เป็นวิธีรับเงิน กรอกช่อง **รับเงินมา** `100.00` บาท ช่องนี้คือเงินสดที่ลูกค้ายื่น ไม่ใช่ราคาสินค้า ตรวจยอดที่ต้องชำระและเงินทอนที่หน้าจอคำนวณ อย่ารับเงินจริงจากลูกค้าทดสอบที่ไม่ได้ตกลงการฝึก
3. กด **รับชำระ** เพียงครั้งเดียว รอข้อความ **ขายสำเร็จ** และเลขใบเสร็จ ตรวจเงินทอนที่แสดง ซึ่งกรณีตัวอย่างที่ไม่มีภาษีหรือส่วนลดเพิ่มควรเป็น 80 บาท กด **ดูใบเสร็จ** และพิมพ์เฉพาะเมื่อเครื่องพิมพ์ผ่านการทดสอบ
4. ตรวจยอดคงเหลือของ SKU ใน **สาขาทดสอบ** จาก 10 เหลือ 9 และตรวจยอดขายในรายงานกะ เงินสดที่รับ 100 บาทไม่ใช่ยอดขาย 100 บาท: ยอดขายคือยอดบิล 20 บาท และต้องทอน 80 บาท หากเริ่มกะด้วย 500 บาทและไม่มีรายการอื่น เงินสดก่อนปิดกะควรเป็น 520 บาท

**ค้าส่ง:** สร้างช่วงราคาในช่อง **Wholesale steps** เมื่อร้านต้องใช้จริง แล้วทดสอบปริมาณที่เข้า/ไม่เข้าช่วงก่อนรับเงิน ราคาขั้นบันไดไม่ใช่การแก้ราคาหน้าจอด้วยมือ และการขายเชื่อจะสร้างลูกหนี้แทนเงินสดในลิ้นชัก ต้องตั้งลูกค้า สิทธิ์ และวงเงินก่อนแยกทดลอง

## Checklist และสรุปหนึ่งหน้าสำหรับพนักงาน

**ก่อนเปิดร้าน:** ตรวจสาขาและเครื่อง → PIN ของตน → สินค้าขายได้/สต็อกพอ → เครื่องพิมพ์/สแกนเนอร์จริง → นับเงินตั้งต้น → เปิดกะ

**ระหว่างวัน:** สแกนหรือค้น SKU → ตรวจ variant จำนวน ราคา → รับเงินตามวิธีจริง → รอขายสำเร็จ → ตรวจ/ส่งใบเสร็จ → เมื่อผลไม่ชัดให้ค้นบิลเดิม

**ก่อนปิดกะ:** ตรวจบิลและตะกร้าค้าง → คืนเงินที่ยังรอ → นับเงินทั้งหมด → ปิดกะ + นับเงิน → ตรวจรายงานและส่งมอบงานค้าง

**Quick reference:** `ขาย 1 ชิ้น` → `เงินสด` → `รับเงินมา` → `รับชำระ` → `ขายสำเร็จ + เลขใบเสร็จ` → `ตรวจสต็อก` → `นับและปิดกะ` หากต้องคืนสินค้า ให้เปิดบิลเดิมและใช้ขั้นตอนคืนตามสิทธิ์ อย่าลดสต็อกหรือจ่ายเงินคืนเองนอกระบบ

## ขอบเขตก่อนใช้กับร้านจริง

- เว็บ POS ต้องออนไลน์ การขายฉุกเฉินแบบออฟไลน์บนมือถือจำกัดเฉพาะสินค้าขายปลีกเงินสดที่เข้าเงื่อนไขและต้องซิงก์ด้วยรายการเดิม ไม่ใช้แทนการทำงานปกติ
- การพิมพ์ ESC/POS, ลิ้นชัก และสแกนเนอร์ต้องทดสอบกับรุ่นจริง; การมีปุ่มพิมพ์ในระบบไม่ใช่หลักฐานว่าอุปกรณ์หน้างานผ่าน
- สินค้าที่มี lot, serial, expiry, ของชั่ง, pack, คูปอง หรือขายเชื่อมีขั้นตอนเพิ่ม ให้เริ่มจากตัวอย่างสินค้าชิ้นเดียวก่อน และดู [บทเรียนค้าปลีกฉบับออนไลน์](https://jachoei.com/th/learn/retail) สำหรับงานต่อยอด
