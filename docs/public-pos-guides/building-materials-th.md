# คู่มือทดลอง BMS POS+ ร้านวัสดุก่อสร้าง PILOT

## สถานะและผู้อ่าน

**PILOT / ยังไม่พร้อมใช้ครบ / ไม่ยืนยันว่า production มี migration และหน้าจอทั้งหมด** คู่มือนี้สำหรับเจ้าของร้าน ผู้จัดการ ผู้ดูแลสินค้า และพนักงานขายที่ซ้อมในร้านทดสอบเท่านั้น งานเฉพาะร้านวัสดุก่อสร้างใหม่ต้องมี migration `10.133`–`10.137` และตรวจในสภาพแวดล้อมที่จะใช้จริงก่อนทดลอง งานส่งหลายเที่ยว ตัดจากม้วน บัญชีเจ้าหนี้ และราคาก่อน VAT หลายช่องทางยังไม่ครบ

ตัวอย่างสอนตั้ง SKU ปูนถุง รับของ เปิดกะ ขายเงินสดหนึ่งถุง ตรวจใบเสร็จและสต็อก แล้วปิดกะ ส่วนใบเสนอราคา สเปกและสินค้าชั่งอธิบายเป็นขอบเขต pilot ห้ามใช้เอกสารนี้เป็นหลักฐานว่าระบบเปิดใช้จริงหรือเอกสารภาษีผ่านการรับรอง

**เตรียมก่อนเริ่ม:** ร้านทดสอบ สาขา ผู้ดูแลสินค้าที่มีสิทธิ์ พนักงานขาย เครื่อง POS เงินทอน ข้อมูลราคาที่สมมติ และผู้ตรวจผล pilot แยกจากลูกค้า/ผู้รับเหมาจริง

## PILOT — ใช้งาน BMS POS+ Desktop สำหรับร้านวัสดุก่อสร้าง

**ผู้ทำ:** ผู้ดูแลร้านทดสอบตั้ง SKU หน่วย และราคา; แคชเชียร์ `pos.sell` ทดลองขายโดยไม่รับเงินลูกค้าจริง; ผู้ตรวจ pilot บันทึกสิ่งที่ยังไม่ผ่าน ห้ามใช้บทนี้เป็นคำยืนยันว่า production พร้อม

1. ก่อนเริ่ม ผู้ดูแลยืนยันว่าร้านทดสอบมี migration `10.133`–`10.137` และเปิดส่วน pilot ที่ต้องใช้แล้ว ตั้งสินค้า `TRAIN-CEMENT-001` หน่วยฐาน **ถุง** variant `STD`, ช่องทาง `RETAIL_POS`, ราคาและสต็อกฝึกที่ตรวจแล้วใน Admin; อย่าอ้างว่าเครื่อง production ใช้ได้จากการเห็นเมนู
2. จับคู่ Desktop กับสาขาทดสอบ เลือกพนักงาน ใส่ PIN เปิดกะ แล้วเข้า **ขาย** ที่ `/pos/app` ค้น SKU ฝึก เลือก **ถุง** จำนวน 1 ตรวจราคา `180.00` บาทและสต็อกของสาขา หากจะแยกพาเลทหรือหน่วยผู้จำหน่าย ให้ตรวจ Pack/supplier-unit ที่ผู้ดูแลตั้งจริงก่อน อย่าให้แคชเชียร์คำนวณอัตราแปลงเอง
3. ในการซ้อมโดยไม่รับเงินจริง เลือกวิธีชำระตามสภาพแวดล้อมทดสอบ ตรวจยอดและเงินทอนที่หน้าจอ แล้วกดยืนยันเฉพาะเมื่อผู้ดูแลยืนยันว่าเป็นร้านทดสอบ เก็บเลขใบเสร็จที่ระบบคืนและตรวจสต็อกสาขา หากผลไม่ชัดให้ค้นบิลเดิม ไม่ยิงซ้ำ
4. ไป **คืน** เมื่อต้องซ้อมคืนบิลเดิม; ผู้มีสิทธิ์ตรวจหน่วยและ lot ก่อนยืนยัน กลับ **กะ** เพื่อนับเงินและปิดกะ ตรวจรายงานและบันทึกความต่าง อย่าใช้ Open item แทนงานตัดม้วน/ส่งหลายเที่ยวที่ยังไม่ครบ

**PILOT / ยังไม่พร้อมใช้ครบ:** เส้นทางขาย SKU ทั่วไปอ้างโค้ด Desktop และ POS แต่ยังไม่ได้ทดลองรายการบนร้านทดสอบผ่านแอปที่จับคู่จริง ฟีเจอร์เสนอราคา สินค้าชั่ง หน่วยผู้จำหน่าย และการส่งหลายเที่ยวต้องพิสูจน์แยก ไม่ถือว่าเปิดใช้ production ภาพที่ 1–2 แสดงเพียง UI สร้างเครื่อง/จับคู่

## ลงปูนถุง รับของ และตรวจสต็อก

**ผู้ทำ:** ผู้ดูแลที่มี `product.edit` ตั้งสินค้า; ผู้ทำ Purchase และผู้รับของมีสิทธิ์ตามงาน; ผู้จัดการตรวจยอดก่อนซ้อมขาย

1. เลือกประเภทร้านวัสดุก่อสร้างใน **Settings** สำหรับร้านทดสอบก่อนออร์เดอร์จริงแรก ประเภทนี้เป็นเพียง starter preset ไม่เปิดฟีเจอร์ pilot โดยอัตโนมัติ ตรวจว่าหน้าเฉพาะทางพร้อมและ migration ใช้ได้ก่อนสร้างรายการ
2. เข้า **Products** สร้าง SKU `TRAIN-CEMENT-001` ชื่อ `ปูนถุงฝึก 50 กก.` เลือก `DIRECT`, หน่วยฐาน `ถุง`, variant `STD`, ราคา `180.00` บาท และช่องทาง `RETAIL_POS` หากร้านขายยกพาเลท ต้องสร้าง **Product packs** พร้อมจำนวนถุงต่อพาเลทจากของจริง ไม่ใช้จำนวนที่เดา
3. ตั้งประเภท VAT ตามการตรวจของบัญชีร้าน หากไม่ทราบต้นทุนอย่ากรอกศูนย์แทนต้นทุนจริง ก่อนรับของตรวจสาขาทดสอบและผู้จำหน่ายสมมติใน **Purchase** สร้าง PO จำนวน 10 ถุงแล้วเปิดใบเดิมรับจริง 10 ถุง ตรวจยอดคงเหลือในสาขา อย่าสร้างยอดตั้งต้นโดยแก้เลขคงเหลือบนหน้าสินค้า
4. งาน supplier unit ต่อผู้ขาย เช่น หนึ่งพาเลทมีหลายถุง เป็น pilot ต้องเก็บหลักฐานการแปลงหน่วยและตรวจจำนวนหน่วยฐานก่อนยืนยันรับ หากยังไม่ได้พิสูจน์ workflow นี้ ให้ซ้อมด้วยหน่วยถุงตรง ๆ ก่อน

| ช่อง | ตัวอย่างสำหรับฝึก | ความหมาย |
| --- | --- | --- |
| SKU / ชื่อ | TRAIN-CEMENT-001 / ปูนถุงฝึก 50 กก. | สินค้าสมมติ ไม่อ้างยี่ห้อจริง |
| สต็อก / ช่องทาง | DIRECT / RETAIL_POS | ตัดจากสาขาเมื่อขายหน้าเคาน์เตอร์ |
| หน่วย / variant | ถุง / STD | หน่วยที่นับจริงในคลัง |
| ราคา | 180.00 บาท | ราคาตัวอย่าง ไม่ใช่ราคาแนะนำของระบบ |
| จำนวนรับเข้า | 10 ถุง ที่สาขาทดสอบ | อ้างใบรับของฝึก |
| VAT | ตามที่บัญชีร้านตรวจ | อย่าเดาสถานะภาษีจากตัวอย่าง |

## ซ้อมขายหนึ่งถุงตั้งแต่เปิดกะถึงปิดกะ

**ผู้ทำ:** ผู้ขายที่มี `pos.sell` บนเครื่องและกะที่เปิด; ผู้ตรวจ pilot เก็บผลทดสอบ ไม่รับเงินจริงจากลูกค้า

1. จับคู่เครื่องกับสาขาทดสอบ เลือกผู้ขาย ใส่ PIN เปิดกะด้วยเงินตั้งต้น `500.00` บาท ตรวจสถานะกะและสาขา
2. เข้าแท็บ **ขาย** ที่ `/pos` ค้น `TRAIN-CEMENT-001` เลือก variant `STD` จำนวน 1 ตรวจชื่อ ราคาและยอด 180 บาท ไม่เลือก Pack พาเลทแทนถุง
3. เลือกเงินสด กรอก **รับเงินมา** `200.00` บาท ตรวจเงินทอน 20 บาทเมื่อไม่มีภาษี/ส่วนลดอื่น กด **รับชำระ** ครั้งเดียว รอขายสำเร็จและเลขใบเสร็จ ตรวจยอดบิล 180 บาท
4. ตรวจสต็อกสาขาจาก 10 เหลือ 9 ถุง ตรวจเงินสดในลิ้นชักจาก 500 เพิ่มสุทธิ 180 เป็น 680 บาทเมื่อไม่มีรายการอื่น จากนั้นนับจริง ปิดกะและตรวจรายงาน

**ใบเสนอราคา pilot:** หากจะซ้อมงานผู้รับเหมา ให้สร้างใบเสนอราคาตามหน้าจอ `/admin/quotations` ตรวจ revision และผู้อนุมัติ ใบเสนอราคาไม่จองสต็อก การเปลี่ยนเป็นออร์เดอร์ต้องตรวจราคาและของพร้อมขายใหม่ สถานะ SENT เป็นการบันทึกสถานะ ไม่ได้ส่งเอกสารให้ลูกค้าโดยอัตโนมัติ อย่าสัญญาว่าส่งมอบหลายเที่ยวหรือปิดภาษีครบจากใบนี้

## Checklist และสรุปหนึ่งหน้าสำหรับพนักงาน

**ก่อนซ้อม:** ยืนยันสภาพแวดล้อม pilot/migrations → ร้านและสาขาทดสอบ → สิทธิ์/PIN → SKU/หน่วย/ราคา/VAT ที่ตรวจ → รับของ → เครื่องและอุปกรณ์จริง → เปิดกะ

**ระหว่างซ้อม:** ตรวจ SKU กับหน่วยขาย → ตรวจสาขาและจำนวนพร้อมขาย → รับเงินตามผลทดสอบ → เก็บเลขใบเสร็จ → ตรวจยอดสต็อกและเงินทอน

**ก่อนจบ:** ตรวจบิล/ใบเสนอราคาค้างและข้อผิดพลาด → นับลิ้นชัก → ปิดกะ → บันทึกสิ่งที่ยังพิสูจน์ไม่ได้โดยไม่อ้างว่า production พร้อม

**Quick reference:** `PILOT` → `SKU + หน่วยฐาน` → `รับของจริงในสาขาทดสอบ` → `เปิดกะ` → `ขาย 1 ถุง` → `ใบเสร็จ + สต็อก` → `นับเงินและปิดกะ`

## ข้อจำกัดก่อนใช้กับร้านจริง

- `10.133`–`10.137` ยังไม่ได้ยืนยันว่าลง production แล้ว การผ่าน build หรือการทดลองฐานทิ้งไม่เท่ากับเปิดใช้ร้านจริง
- สเปกสินค้าต้องมีแหล่งอ้างอิงและผู้ตรวจอีกคนก่อนเผยแพร่; สินค้าชั่ง prefix 22 เป็น pilot เฉพาะ POS ขายปลีกและต้องทดสอบเครื่องชั่ง/ป้ายจริง
- การตัดสายไฟจากม้วน การส่งของหลายเที่ยว/รายบรรทัด บัญชีเจ้าหนี้ และราคา B2B ก่อน VAT ข้ามช่องทางยังไม่ครบ ห้ามใช้สินค้าชั่วคราวหรือหลักฐานค่าใช้จ่ายแทน workflow ที่ขาด
- ใบเสนอราคาไม่จองสต็อก และหน้าสรุปลูกหนี้ภายในไม่ใช่หลักฐานว่าแจ้งหรือเก็บเงินแล้ว ดู [คู่มือวัสดุก่อสร้างฉบับออนไลน์](https://jachoei.com/th/learn/building-materials) เพื่ออ่านสถานะล่าสุดก่อนซ้อมรอบใหม่
